# 后续实施与恢复约定

生效：2026-10-10。适用于后续开发、部署、验收、文档维护及恢复任务。
来源是 [HM-MVP 实施复盘](../hosted/hm-mvp-implementation-retrospective.md)。
本约定用于控制返工、资源和证据风险，不增加新的开发门禁、测试、独立审批或资格流水线。
既有冻结契约与科学、安全判据继续按原版本执行；修订采用明确的后继版本。

## 1. 从已有结果开始

先读取当前状态、接受范围与已有授权，再确定本次变更和实际依赖。
以现有任务说明或交接记录简短回答：改什么、复用什么、只需新增什么。
纯文档和简单修改直接说明即可，不另造审批包或机器可读清单。

已完成、原件可取得且身份/依赖可核对的冻结、安装、输入、CI、场景、gate、
科学结果、export/replay 和 checkpoint 必须优先复用。
不能复用时，在执行前说明具体缺失或变化的依赖、受影响结论与最小补做范围。
整体 commit、管理路径或文档变化不能单独作为全量重跑的理由。

保持原证明的 originating tuple、实际执行记录和采用范围。文件未变不自动证明
行为等价；传递依赖、schema、配置、运行环境及权限变化均须考虑。
跨版本采用在新的组合说明或接受记录中明确，不把旧 PASS 改标为新 tuple PASS。

## 2. 控制验证范围

- 不新增非必要开发门禁或测试；只有用户明确要求测试或验证实现时才新增或运行测试。
- 开发阶段先做必要的静态、接口和布局检查；获授权的验证优先使用已有受影响用例。
  格式、夹具、管理脚本和路径问题不默认触发完整 CI、矩阵或科学重执行。
- 完整验收在稳定里程碑及确有依据的影响范围内执行。全量执行前说明为何局部验证不足，
  复用哪些已完成部分，并核对资源预算；不为填写说明另设审批步骤。
- 一次失败先查看有限失败信息和已完成结果，修正该环节。原因未明时不盲目重试整轮、
  扩大超时、增加额度或重冻结全部材料。
- 合并同次验证中的重复完整调用与大文件读取。缓存只用于确定性、不可变且身份已核验的事实；
  不用文件名、mtime、宿主自报 PASS 或旧摘要代替原件和机械核验。

新验证器或缓存的依赖应包含实际相关的源码、输入、schema/policy、配置、环境、
场景参数和 verifier 版本；总体 commit 仍保留作追溯身份。
验证输入应使用稳定不可变库存，发布输出与控制记录放在其检查集合之外，避免自引用和
“发布一个结果导致原证明失效”。不得直接修改冻结 verifier 来静默缩小原分母。

## 3. 尽早确认关键接口

涉及外部 runtime、账户或新 transport 的任务，尽早贯通最小真实交接，核对固定版本、
事件/usage、schema、候选真实身份映射、canonical bytes 及下游报告读取路径。
先用已有接口与有限静态检查定位可发现的问题。
真实调用必须已有明确授权和可用额度；开发探路不授予最终资格。
已有接受路线不重复探测，只有相关依赖变化才补做必要部分。

## 4. 正式证据持久化与断点恢复

正式成功、失败、拒绝、退出、receipt、来源绑定和关键 checkpoint 从开始就保存在
持久证据目录；禁止以 `/tmp`、`/var/tmp` 或自动清理缓存作为唯一权威存储。
scratch、构建缓存、测试临时文件与正式证据分开，并有明确生命周期。

每个可独立完成的耗时场景或 gate 结束后及时持久化结果、依赖身份和实际退出。
现有入口缺少结果出口时，补齐最小保存能力，或在启动前说明不能续接的范围与成本，
不等整项结束才发现中间工作无法复用。仅观察到进程存活或 prelaunch 不算已完成。

恢复先对账原件及来源，保留已完成部分；从未完成或依赖已变化的部分继续。
父作业失败不自动否定其已保存、完整核验的独立结果，也不能把父失败改标为成功。
未保存或缺少来源的结果不凭推测补写；不修补历史 proposal、wait 或 producer 字段。

## 5. 容量与性能

重任务启动前确认真实物理卷与宿主映射，计算输入/安装副本、科学中间输出、
export/replay、写时复制增长、并发 worker、失败留证及安全收尾的完整增量。
WSL 内部 free 不代替宿主卷余量；各任务不能重复预留同一空闲空间。
只读共享或实际支持的 reflink 优先；可写 hardlink 不能用作独立 authority。

继续使用已有硬配额、空间守卫与清理机制，不因本约定另造一套资源框架。
task 写入预算与整卷安全监测口径应区分；整卷增长不能无观测地归因某个任务。
保护触发时及时保存有限的卷余量、估算、作业身份和实际退出，不记录秘密或原始敏感日志。
不得为促成成功放宽既有安全底线，也不得删除唯一正式失败证据腾空间。

对耗时长或成本不明的阶段，利用既有运行记录了解 wall time、CPU time、扫描字节/次数、
文件数及可观察的资源峰值；不可观察项标为 unavailable。
先优化反复解析大文件、科学重执行和重复完整核验等大头，不凭印象归因 CPU 或磁盘，
不为建立统计另跑一遍完整流程。失败次数或 attempt 编号不等于完整运行次数。

## 6. 依赖与资源允许时并行

独立场景、独立 replay 根、源码阅读、必要静态检查和文档准备在资源允许时并行。
共享输入只读，输出根独立，统一预留 CPU、内存、物理卷容量和失败清理空间。
同一可写 authority、同一场景 crash→recovery→对账以及依赖前次结果的提案继续串行。
不能默认所有任务串行，也不能因核数多就无限加 worker。
不增加无必要的代理编排；子代理使用遵守当次任务和上级指令的授权范围。

## 7. 授权、报告与交接

复用已明确授予的授权及偏好；可逆、只读或已授权操作不重复请求同范围确认。
费用/调用额度、外传范围或不可逆操作确实超出原授权时，先完成具体可审阅材料再申请。
不能把源码 hash 变化自动解释为所有授权失效，也不能据原授权扩大模型额度、reissue 或 TTL。

当前状态和下一步保持短页；历史失败、过期和旧 pending 按原时点留存。
完成时简短记录新增结果、复用范围、实际执行和未解决事项，不在多个入口重复大段历史。
Agent 复审、工程接受、科学报告和研究结果分别表述。

## 8. 尚需实现的能力

本页是后续工作约定，不表示已实现通用的依赖驱动增量验证、自动 checkpoint 恢复、
共享卷资源调度或任务级精确写入归因。后续任务若需要这些能力，优先复用现有组件并
按实际范围补齐；不因本页自动立项、启动模型、测试、重冻结或重跑验收。
