# HM-MVP 实施复盘与教训

日期：2026-10-10。范围：P14 RC 之后至 component-v2 MVP 工程交付完成。
后续实施使用[实施与恢复约定](../guides/implementation-discipline.md)；仓库根 AGENTS.md
和开发指南均要求读取该约定。本文解释依据，操作规则集中维护在约定页。

## 结论

9月29日原始方案至10月10日交付跨度约11天。主要延误机制是局部问题反复扩大为
整轮证明失效、昂贵重跑和资源增长；容量事故及临时证据不可取得又放大了恢复成本。
关键接口风险发现过晚、管理工具缺陷、checkpoint 缺失和串行调度共同延长了关键路径。
实施方对验证范围、复用设计、资源规划和风险发现顺序负有改进责任。

科学执行与真实隔离确有必要成本，但不足以解释全部返工。PIT、凭据保护、隔离和
不可变证据继续严格；应优化其证明方式、依赖范围、持久化和恢复能力。
最终 component-v2 的组件采用、四项 PASS 复用及独立回放说明无需重复全部重流程即可收尾。

## 原因与改进对应

| 原因 | 实际问题 | 后续必须采取的做法 |
|---|---|---|
| 验证范围过大 | 格式、夹具、路径和等待问题在数小时 CI 或 native 中才发现 | 静态/接口/布局问题前置；受影响验证优先，全量重跑说明必要性 |
| 重复核验 | CLI 曾在 verify_bundle 后再次核验；Q05 反复解析大型结果 | 去掉重复完整调用，复用同次核验的确定性事实，测量真实大头 |
| 证明失效范围粗 | 总体 tuple 变化缺少组件采用入口，局部修复导致广泛返工 | 记录实际依赖闭包与 originating tuple，明确跨版本采用范围 |
| 库存与输出耦合 | Q08 返回整个 manager/evidence 库存 hash，发布 export 又改变它 | 固定验证输入库存，将发布输出/控制记录置于检查集合之外 |
| 证据生命周期错误 | 正式运行和来源原件大量位于 /tmp，恢复后不可取得 | 正式证据从开始持久化，缓存与 scratch 分开，逐项及时发布 |
| 容量模型不足 | WSL free 与宿主卷容量未充分对应，副本/回放/失败留存累计 | 绑定实际卷，统一并发预留完整增量，保留安全收尾空间 |
| 保护口径与诊断不足 | 整卷 free 下降按任务估算判断，未保存触发瞬间样本 | 区分任务增长与整卷安全监测，触发时留存有限公开事实 |
| 关键接口晚验证 | 后期才发现模型路线、CLI格式、schema、身份与canonical字节问题 | 有授权和额度时尽早最小真实贯通；静态可发现问题先校对 |
| 管理工具缺陷 | 缺 max_bytes、挂载SRC错误、大索引reader不一致、git index副作用 | 使用现有严格reader/序列化API，有限检查完整消费路径，保持只读 |
| 缺少中间结果 | 首次候选 view 未保存 gate，异常只有类型，无法复用未落盘结果 | 独立步骤完成即保存身份/结果/实际退出，失败后只续未完成部分 |
| 调度偏串行 | 部分矩阵单worker，独立场景和准备任务并行不足 | 按依赖与共享资源安排并行，保留同authority和恢复链的必要顺序 |
| 交接与授权反复 | 小修改带来新tuple/审批材料，大量历史pending占据当前入口 | 复用原范围授权，当前短页与完整历史分开，减少重复包装 |

### 典型案例

**Q08 发布导致结果不一致。** source03 新增 manager export 后父库存变化，
旧 saved Q08 checked hash 与重新核验不同，虽然其它 gate verdict/reason/checked hashes 一致。
这不是已证实的 hash seed 缺陷，不能仅凭 case 文件未变就推断所有依赖未变。
见[实施历史中的 native03](hm-implementation-history-2026-10-10.md)。

**事故与临时证据。**恢复后原管理根、工作树、wheel、observer 等在当前视图不可取得，
但固定 snapshot、Qlib view、release 和冻结 Git 对象仍可见。不能表述成所有科学输入失效，
也不能把不可访问等同永久删除。事故损失与后续安全守卫中止分别分析；
现有记录不足以还原最初事故的具体写入者或完整系统故障路径。
见[存储恢复记录](hm-storage-recovery.md)及实施历史的恢复开发第一阶段。

**事故后保护与夹具。**第39轮 CI 有680项私有512MiB /tmp ENOSPC 相关失败；
之后还有证据位置限制、fakeSDK 临时路径及 profile fixture 不匹配。
保护本身必要，旧夹具与新环境的接口问题应在局部暴露，不应多次交给完整 CI 发现。

**真实提案接口。**旧 CLI/认证路线拒绝目标模型；CLI0.162.1 路线取得实际响应后，
又暴露事件/usage适配、schema、candidate content_hash 未提供及非canonical JSON问题。
其中第二提案字节被原规则拒绝后不能人工修补原提案；需要保留失败并在合法新范围内修正。
改进重点是提前正确表达接口，不降低 proposal 接收规则。

**断点复用生效。**verify02 空间守卫中止前保存四份 canonical PASS。
continuation01 绑定原来源直接复用四项，仅续做 Q11 及收尾，实际0/fullcleanup。
父 -15 失败保留，没有把它改标成功。最终独立接受范围见
[HM09 报告](../reviews/hm09-component-v2-final-review.md)。

## 应保留的做法

- 保留真实失败、过期和缺证，不伪造历史退出或以摘要替代原件。
- 沿用 Qlib 与确定性科学链，工程接受与 SOFT_REJECT 科学结论分开。
- 最终采用有范围的组件证明、只读来源映射和已保存 checkpoint，复用原重流程。
- 独立 replay 根允许安全并行，最终独立工程复审与文档登记职责明确。

## 落实顺序与责任

立即适用于后续任务的是：读约定、默认复用、明确局部影响、正式证据持久化、
已有授权复用、控制验证范围、资源允许时并行及短交接。
任务负责人执行这些要求，并在现有任务记录中说明实际选择和未解决限制。
需要重任务时由执行方先说明理由和预算；最终审阅者核对声明范围与实际记录。

通用增量依赖图、自动断点恢复、资源调度和精确写入归因是尚需按需求补齐的工程能力。
本复盘不宣称它们已实现，不自动启动它们，也不为复盘再跑 CI、矩阵、模型或冻结流程。
用户明确授权与偏好继续有效，既有接受工件和历史规则按原身份留存。
