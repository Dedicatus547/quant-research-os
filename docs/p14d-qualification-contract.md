# P14d-B autonomous campaign qualification contract v1

Status: **frozen and QUALIFIED for the clean-commit double-root runner**
Authority: bounded deterministic autonomous research engineering evidence only.

## Scope

P14d-B qualifies the frozen deterministic autonomous control plane, not a live Agent runtime.
The qualification uses `ScriptedAgentDriver` and `ReplayAgentDriver`; it performs no model call,
network access, Codex SDK invocation, CLI fallback, or runtime integration. The autonomous
campaign path remains bounded by the frozen P14d-A candidate manifest, campaign governor,
Research Ledger, ContextPack, immutable execution receipts, verified ResearchResult artifacts,
ValidationReport, and the real P14c `CampaignSelectionService`.

The runner is `scripts/p14d_qualification.py`. It requires the exact clean Git root of this
repository, binds the implementation commit, `uv.lock`, Python/runtime fingerprint, frozen
qualification contract, Qlib source/version binding, fixture hashes, autonomous policy hashes,
execution bindings, and P14c selection plan hashes, then executes two fully independent roots.

## Frozen fixture inputs

Qualification uses two committed synthetic offline fixtures under
`tests/fixtures/p14d_qualification/`:

- `selected`: a real Qlib LGBModel workflow produces a validation Rank IC whose P14c Holm
  bootstrap decision is `SELECTED`.
- `no_selection`: the real Qlib workflow produces validation evidence whose P14c decision is
  `NO_SELECTION`.

Both fixtures bind a prebuilt native Qlib 0.9.7 view generated by the official Qlib
`dump_bin.py` and `check_data_health.py` tools. No network download is used. The snapshots and
views are derived caches of synthetic canonical fixture data and never market evidence.

## Canonical cases

Each root executes exactly these canonical cases in order:

1. `SELECTED`: two Agent iterations, one real PIT/Qlib/Validation execution, one
   `SCHEMA_INVALID` disposition, Ledger refresh, refreshed ContextPack, P14c
   `SUCCEEDED / SELECTED`, `SelectionFrozen`, and
   `READY_FOR_SEALED_CONFIRMATION`. The runner never appends `OOSAccessed`.
2. `NO_SELECTION`: two Agent iterations, one real execution, one non-success disposition,
   complete accounting, P14c `SUCCEEDED / NO_SELECTION`, and campaign closure without sealed
   authority.
3. `FAILED_NOT_EVALUATED`: a known injected PIT rejection at the deterministic execution
   adapter boundary plus a schema-invalid disposition, producing complete accounting,
   P14c `FAILED / NOT_EVALUATED`, and no fabricated selection or sealed authority.

The injected PIT case is deliberately labelled fault injection; it is not real market data.
Canonical `SELECTED`/`NO_SELECTION` evidence uses the real PIT, Qlib workflow, Qlib Simulator
backtest, Validation, immutable ResearchResult, campaign, Ledger, ContextPack, and P14c
services.

## Negative qualification

Each root runs the complete negative case set and records deterministic evidence that the
authority path fails closed. The set covers manifest drift, candidate hash/AST/fingerprint
mismatch, snapshot and Qlib view mismatch, policy mismatch, stale ContextPack and stale Ledger
snapshot, tampered Agent exchange/replay/receipt/ResearchResult/ValidationReport, conflicting
execution retry, conflicting trial identity, duplicate proposal accounting, compute-budget
exhaustion, max Agent runs, max trials, unknown candidate, invalid proposal schema, PIT
look-ahead rejection, execution failure, Ledger chain corruption, P14c report tamper, and
selection mismatch. Integrity/authority failures raise typed orchestration errors; known
execution failures produce deterministic `PIT_REJECT` or `EXECUTION_FAILED` evidence.

## Restart qualification

Each root qualifies three crash/restart boundaries with real execution:

- `AGENT_EXCHANGE_AND_EXECUTION_RECEIPT_BEFORE_TRIAL`: restart reuses the immutable exchange,
  execution receipt, ResearchResult, and CampaignTrial without a second AgentRun or Qlib run.
- `CAMPAIGN_TRIAL_COMMITTED_LEDGER_RECONCILIATION_INCOMPLETE`: restart completes Ledger
  reconciliation from the committed trial and does not duplicate it.
- `P14C_REPORT_PUBLISHED_SELECTION_EVENT_NOT_COMMITTED`: restart reuses the verified report and
  commits exactly one `SelectionFrozen`.

The runner verifies exact counts for exchange artifacts, execution receipts, ResearchResult
artifacts, trial events, selection events, and observed Qlib workflow invocations.

## Replay qualification

Replay loads an already published Agent exchange, verifies its request/response binding,
returns the same proposal bytes and hash, resolves the same frozen candidate, and reuses the
existing execution identity and receipt without invoking Qlib again. Replay never promotes
authority.

## Double-root equality

`root-A` and `root-B` are created in separate output trees. They share only immutable source
fixtures, source tree, lockfile, and runner code. They never share exchange artifacts, execution
output, ResearchResult artifacts, campaign event stores, Ledger roots, selection artifacts,
loop reports, or qualification result caches.

For every canonical case the roots compare candidate manifest hash, initial ContextPack hash,
Agent request/proposal hashes, execution request identities, ResearchResult hashes,
ValidationReport hashes, CampaignTrial hashes, campaign event hashes, Ledger principal hashes,
final Ledger snapshot hash, P14c report hash, `SelectionFrozen` hash when applicable,
AutonomousLoopReport principal hash, and case summary hashes.

Wall-clock duration, temporary directories, process IDs, random paths, MLflow local paths, and
runtime timestamps are outside the deterministic principal domain. Compute authority uses the
frozen deterministic compute-accounting policy, not observed elapsed runtime. The authoritative
comparison is exact: no mismatched field is ignored.

## Qualification report

The runner publishes exactly one content-addressed immutable
`P14dQualificationReport` under `artifacts/qualification/p14d/sha256-...`. The bundle contains
the exact-file manifest, code provenance, runtime fingerprint, lockfile, frozen qualification
contract, both complete root trees, root evidence, and the report. Verification rejects missing
or unexpected files, non-canonical bytes, hash/path mismatch, tampered provenance, replayed
fixture mismatch, and non-reproducible root evidence. A caller cannot supply `PASS`; the
verdict is constructed only after all canonical, negative, restart, replay, equality, and
engineering gates pass. Verification re-runs both roots bottom-up in a fresh temporary tree.

## Verdict and limitations

The only admitted final status is `SUCCEEDED / PASS`; any missing gate is `FAILED / NOT_EVALUATED`.
The report must declare:

```text
SYNTHETIC_OFFLINE_ENGINEERING_EVIDENCE
```

It establishes only that the bounded deterministic autonomous research control plane can be
independently reconstructed under frozen synthetic offline inputs with byte-identical
authority evidence. It does **not** establish real market alpha, profitability, historical
vendor-vintage PIT qualification, live Agent qualification, production LLM qualification, or
sealed-confirmation qualification.

## FR-03 boundary

Codex CLI, or another runtime, remains outside this contract. FR-03 remains `NO_GO`, P14d-C
