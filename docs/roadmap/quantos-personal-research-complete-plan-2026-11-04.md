目标是交付可持续使用的完整个人研究助手：研究方向 → 有依据的策略方案 → 确定性执行与对照 → 可解释结果 → 历史反馈 → 有界后继研究 → 冻结策略的连续前瞻能力。最小接口只是内部实施步骤，不是最终交付。

## 一 交付目标和完成口径

用户只需给出方向及必要的市场、数据和预算约束。模型负责设计策略、选择合理对照、解释证据和提出继续或停止建议，不让用户填写内部哈希或逐项设计指标。系统负责确定性计算、权限、时间语义、预算、原生账户及不可变结果。

完整交付包括：

1. 可执行的日频量价策略表达，包括评分、筛选、组合构建及有限持仓规则。
2. 个人 Skill/MCP 中从准备到结果的完整路径，支持比较、取消、恢复及有界后继研究。
3. 有来源的诊断报告和可用于下一次研究的历史记录。
4. 新快照接入、冻结策略信号观察和原生连续影子账户的工程能力。
5. 本机安装、实际客户端连通、兼容性检查及可复制的使用和恢复说明。

区分三种交付状态，不以其中一种替代另一种：

| 状态 | 必须具备的事实 |
|---|---|
| 工程完整交付 | 本计划 W0–W7 的必要行为实现并通过适当验证；账户连续性不能只提交接口或返回未实现 |
| 真实运行就绪或受阻 | 有具体的策略、数据覆盖、缺口、预算、执行范围和准备包；没有执行的明确标为未运行 |
| 真实研究或前瞻观察完成 | 按另行有效授权真实执行，保存实际结果；未来观察只能随时间积累，不能用历史回放替代 |

工程验收不要求盈利、固定迭代轮数、独立确认成功或取得 P14d-C 资格。若连续账户或其他必需能力未解决，报告“部分完成及具体阻塞”，不能自行删去要求后宣称完整交付。真实采集尚未授权不阻止离线实现和工程验收。

| 事项 | Codex可自主采用的默认值 |

## 四 核心接口与身份设计

以下是逻辑职责，不要求逐项新建类、服务或文件。优先扩展已有后继契约，保留旧canonical bytes及读取路径。

| 对象 | 必须表达的内容 |
|---|---|
| 研究请求 | 用户方向、假设、数据范围、历史引用、提案来源；解释文字不是算法 |
| 策略规格 | 评分表达式、显式资格条件、排名方向和并列规则、组合、调仓与退出语义 |
| 执行政策 | 交易时钟、费用、数量单位、容量、成交限制、权益边界和Qlib运行依赖 |
| 准备结果 | 解析后的全部执行参数、数据和PIT依赖、可执行性、具体缺口、候选和对照分母、预算估算 |
| 信号与运行输入 | 策略身份、数据身份、PIT lineage、可得时间、信号/决策/执行时钟及原生适配身份 |
| 研究结果 | 完整尝试分母、每行终态、原生账户原件、指标定义、复用来源及科学状态 |
| 反馈记录 | 假设、观察、反例、解释、适用范围、引用、未回答问题及继续/停止理由 |
| 观察与账户检查点 | 冻结策略、数据截止、快照链、原生状态、最后完成步、输出引用与实际退出 |

分别绑定研究说明、策略、数据、执行政策和运行依赖。仅改brief不得被描述为算法变化；算法改变不得借用旧signal_reuse；main/classic/random只表示报告角色，不再分派新路径的算法。账户复用还须核对初始资金、时期、实际信号、执行政策与运行依赖，不能仅靠策略名或相同评分复用。

信号适配保留来源和PIT语义。输入lag与next-session执行lag各施加一次；预热不足、除零、非有限值、缺字段、未知时间和非交易日都有明确处理。截面运算只使用该时点已知且合格的成员，不能把时序Rank冒充截面排名。

当前历史reader读取JSON；新增知识记录采用带引用的派生JSON或明确版本化reader，不能把Markdown路径直接塞入旧reader。索引可以重建，原件与原始结论是权威，模型解释只能作为提案或注释。

知识记录含适用股票池/时期/数据与成本情景、假设、观察、支持与反例引用、解释、不确定性、失效条件和修订关系。事实、模型解释和代码修复经验分开；修订追加后继，不回写历史结论。检索先按结构化标签与文本改善现有目录；未来数据/结果不能泄入旧时点的记忆。

以confirm2、原七组结果和现有换手归因为首批案例。优先读取已有派生指标，缺失统计仅做必要有界离线计算，不重跑账户。旧报告不是新Validation；原件缺失时明确只可引用报告的范围。

保留公告材料读取和引用，作为同一研究任务的辅助证据。记录人工干预次数、可观察耗时、重复提案、失败原因和输出体积，能顺带测量才测量，不另开无记忆竞赛或性能实验。

完成条件：研究准备能找到相关事实与反例，结果形成可读取的引用记录；确认实验只能被概括为“在该范围未获支持”；没有第二套结果权威。

### W5 前瞻数据和信号观察

实现新快照准备/接入及离线信号观察；采集只能调用既有snapshot acquisition层。研究MCP不能临时联网取市场数据。每次输入绑定显式snapshot/view与策略版本，保留采集时间、来源可见时间、输入截止和信号发布时间。

开发使用有序合成快照及已有允许读取的冻结数据；实际新采集按运行授权执行。冻结后真实到达的信息才算未来观察。新快照修订旧历史时保留前序版本和修订关系，不回写已发信号。使用复权序列时明确跨快照因子/数量单位一致性，不能静默重标旧账户。

记录每个计划观察日的发出、弃权、缺失或停止及其原因。迟到数据可以创建事后补算记录，明确区别于当时已发信号，不覆盖缺失日。策略改动创建新观察版本，不拼接成同一连续表现。

完成条件：合成到达序列覆盖正常、缺失、迟到、修订和非交易日；时钟和快照身份可追溯；没有将2026年数据天然标成未曝光样本。

### W6 原生连续影子账户

检查点至少绑定原生账户与策略实际所需状态、累计指标、已处理交易日、策略/政策/引擎版本、前后快照、上一检查点、信号/订单/成交原件和完成收据。仅保存Position字典或pickle文件不足以宣称连续性。可信本地制品才允许加载，拒绝未知来源的可执行序列化输入。

验收比较同一受支持数据和政策的完整执行与分段推进，覆盖现金、持仓、成交、费用、NAV和累计报告。数值容差在观察差异前按数值精度确定，身份与离散事件须精确一致。覆盖至少一次带持仓重启、部分/未成交、重复推进、执行后发布前中断及快照衔接。依照原生引擎能力明确可卖限制，不能凭工程用例授予完整交易所规则资格。

未知或不支持公司行动继续显式停止。已有复权单位情景不新增独立现金分红；跨快照复权改变无法安全衔接时停止并保留状态，不自写权益转换分录。

完成条件：完整原生连续账户及恢复通过离线验证，可在授权后接真实新数据；只有前瞻信号记录、持仓导入或接口桩均不算完成。若受阻，交付具体原生接口证据、已完成范围和最小下一选择，保持W6未完成。

## 七 连续实施和授权边界

### 配套启动指令生效后的范围

配套TXT是供用户发送的授权文本。仅在用户实际发送，或明确指示采用其中授权并执行时生效；文件存在、被读取或索引引用都不等于授权。

启动文本一次性覆盖W0–W7本地实现、必要实现验证/定向测试、小型合成原生演练、已有证据读取、本产品用户级安装与只读连通，以及本地任务分支/提交。公共免费依赖须固定版本、检查许可、隔离安装并核算资源，不覆盖旧科学环境。

允许主代理在资源允许时使用最多两个子代理，不递归委派；默认继承可用模型，不强行购买额度、切换账户或使用计划中不存在的模型。工具不可用时串行完成。主代理负责共享契约、集成、安装和最终接受；子代理适合独立CI/展示、反馈/文档等文件范围。此授权是未来启动范围，本轮写计划不启动子代理或实施。

开发外层会话可以生成提案，不新增内部研究SDK或收费服务。允许第二引擎的有限免费离线可行性调查，不自动授权替换主引擎、改变科学政策或真实运行。

### 仅在真实边界请求决定

以下动作没有适用的既有明确授权时，完成具体材料后集中请求：新增采集/数据采购/付费调用、真实市场训练回测或正式Validation、真实前瞻推进与定时任务、主引擎迁移、外部披露、push/远端部署/合并、目标/来源/权益政策的实质改变、破坏性操作。不要从历史启动文档或已终态任务继承额度。
