## 1. 决策摘要

**`post-hm-mvp-research` 已经形成实际研究流程，不再只是设计文档。下一阶段不应优先扩大搜索规模，而应提高现有流程产生可分析、可比较结果的能力。**

| 维度 | 检查结论 | 后续处理 |
|---|---|---|
| 功能实施 | 冻结前生成、能力准入、singleton 子任务、阶段恢复和只读预测比较已有实质性交付 | 保留并复用，不重新建设平行架构 |
| 工程收尾 | 已检查 main 的 CI 在格式检查处失败，后续检查和测试被跳过 | 先修复局部问题，明确实际检查范围 |
| 首轮研究 | 15 个生成机会形成 10 个全局不同候选；5 个预测可分析，5 个执行失败；策略 Validation PASS 为 0 | 保留全部结果，先诊断失败而非扩大调用 |
| LLM 增量 | 4 个成功响应归一化后只有 1 个不同 AST，该候选未产生可分析预测 | 不能估计有效预测增量；优先改善生成设计 |
| 成本 | 已有批次及任务耗时，但完整费用和细分资源仍不充分 | 利用已有阶段记录，按实测决定是否缩短执行路径 |

功能与实验结果来自交付报告及源码；CI 状态来自上轮读取的 Actions 作业及日志。本地评估另核对了机器报告身份与摘要，并复现两个格式问题，未重跑 CI。[R1][R2][R3][R17]

**推荐主线：**

```text
立即并行：N0 局部收尾、N1 失败诊断、N4a 既有成本分析
同时设计：先明确 N5 投入决策问题，再确定 N3 顺序生成方案
                         ↓
按需实施：N2 定向修复或预测证据出口、N3 逐次历史绑定
          N4b 执行优化仅在成本证据支持时启动
                         ↓
冻结评价规则、生成方案与预算 → 获授权的小规模对照
```

N5 的研究设计前置，实际运行后置。N2 与 N4 共用预测证据接口设计；N4b 的执行缩窄不作为 N2 或第二轮的默认前置条件。

**本阶段要准确解释每个候选的可评价性、失败、重复与成本，并据此决定是否继续投入 LLM 生成。提高多样性是中间目标；科学阈值和工程完成条件保持各自含义。**

## 4. 首轮结果应如何解释

### 4.1 方法结果与完整分母

| 方法 | 固定生成机会 | 方法内不同候选 | 可分析的不同候选 | 最佳观测 Rank IC | 策略 Validation PASS |
|---|---:|---:|---:|---:|---:|
| LLM | 5 | 1 | 0 | 不可取得 | 0 |
| TEMPLATE | 5 | 5 | 3 | 0.0070288491 | 0 |
| RANDOM | 5 | 5 | 3 | 0.0209819185 | 0 |

模板与随机共享一个可分析候选，因此全批为 **10 个不同候选、5 个可分析预测**，不是 11 个候选或 6 个可分析预测。LLM 的 5 次机会包括一次网络失败；另外 4 个成功响应只有一个不同 AST。上述值来自首轮报告。[R1]

主指标是**固定 LGBModel prediction 的每日横截面 Rank IC 均值**，不是原始表达式自身的 IC，也不是组合收益。五个可分析预测对应的原策略均为 SOFT_REJECT；这些不同对象的结论可以同时成立。[R1][R6]

本轮不能证明随机搜索普遍优于 LLM，不能把 LLM 的缺失分数当作零，也不能从没有策略 PASS 推导工程流程无效。它已经足以支持一个投入判断：**当前 LLM 生成配置存在明显重复，现有候选存在较高的不可评价比例，直接增加同类调用不是优先动作。**

### 4.2 五个失败的已知事实

下表使用报告中的 `close` 简写；本轮实际开放逻辑字段为 `adjusted_close`。计数只说明原报告的失败现象，不等于根因已经确认。[R1][R5]

| 候选 | 来源 | 已记录现象 | 下一步需要回答的问题 |
|---|---|---|---|
| `close / rolling_mean(close,10)` | LLM | QLIB_EXECUTION_FAILED；Rank IC 有 12 个 NaN | 哪些日期无定义？预测退化、样本不足、标签或对齐问题分别是否存在？ |
| `return(close,5)` | TEMPLATE | QLIB_EXECUTION_FAILED；IC 有 2 个 NaN，Rank IC 有 6 个 NaN | 两种统计的失败日期是否相同？原生与导出证据是否一致？ |
| `abs(return(close,10))` | TEMPLATE | QLIB_EXECUTION_FAILED；Rank IC 有 72 个 NaN | 是否集中于某些日期、样本状态或预测分布？ |
| `abs(close / rolling_mean(close,10))` | RANDOM | QLIB_EXECUTION_FAILED；Rank IC 有 12 个 NaN | 与无 abs 候选是否在实际有效输入域产生相同输出及相同失败？ |
| `rolling_std(close,10)` | RANDOM | SOURCE_INCOMPLETE；baseline-signal 阶段失败，未执行模型 | 是 PIT 成员映射、tradability 证据还是其他来源缺失？ |

常数输入会使 Spearman 相关系数无定义并返回 NaN，但这只是需要检查的一种机制，**不是对本轮失败根因的认定**。[R16]

### 5.3 派发、接续与并行顺序

```text
第一波：主 agent 起草 D04
        A 执行 D02
        B 执行 D01 → D03
                     ↓
主 agent 结合诊断定案 D04，分配公共文件和证据输出归属
                     ↓
第二波：A 执行 D05
        B 执行 D06 → D07
        主 agent 处理接口衔接和具体未决项
                     ↓
按 D03 判断 D08 是否值得实施 → D09 集成
                     ↓
D10 获授权的生成分析 → 按规则决定科学执行 → 交接
```

顺序表示真实依赖，不要求等整波结束才处理已就绪任务。主 agent 收到交付后检查其来源、改动和未决项，即接续下一项；独立工作遇到阻塞时继续其他就绪任务。大原件解析只交给 D02 的负责人，D03 使用阶段记录，避免两个代理重复扫描预测文件。重计算的并行仍需统一 CPU、内存、宿主卷和失败留证预算；同一 authority 的写入及 crash→recovery 链保持串行。

使用当前会话原生子代理工具，不为此安装新调度平台。若提供 `collaboration.spawn_agent`，新建工作代理时显式传入 `model`、`reasoning_effort` 和 `fork_turns="none"`，附第5.4节短任务包。例如首轮 A/B 的配置分别为：

```json
[
  {"task_name":"discovery_failure_diagnosis","model":"gpt-6.1-sol","reasoning_effort":"high","fork_turns":"none"},
  {"task_name":"discovery_local_closeout","model":"gpt-6-luna","reasoning_effort":"low","fork_turns":"none"}
]
```

以上是配置字段示例；实际调用还必须提供完整任务消息，并遵守当次工具接口。同模型、同强度且上下文仍相关时，用原生 follow-up 工具接续同一代理，例如 D02→D05。D01→D03、D06→D07 等配置变化，只有工具明确支持才原地切换；否则保存短交接，停止向旧实例派发工作，使用目标配置新建后继。不能只在消息里要求“改用 medium”就声称实际模型配置已改变。

主 agent 记录派发工具实际返回的身份与可观察配置；不可观察项如实标明。请求的模型不可用时，先沿第5.5节降级或升级规则处理并说明实际配置。缺少子代理工具时，报告这一具体限制并继续可独立完成的授权工作，不假称已并行调度。不要为查模型是否可用另发研究模型探测调用。

### 5.4 文件归属、任务包与持久交接

派发前在现有[实施记录](post-hm-mvp-implementation.md)追加简短的“后继实施调度”区，保留首轮完成历史。主 agent 独占更新任务状态、公共接口决定和汇总；记录任务、实际代理/配置、依赖、写入文件/输出根、交付路径和待办即可，不新增审批包。

写入按文件归属隔离：D01 仅处理指定格式文件与分配的导航页；D02/D03 的历史原件只读，后继分析写入各自的持久目录；D05/D06 修改各自分配的模块。`contracts/discovery.py`、`discovery_comparison.py`、`discovery_report.py`、`scripts/post_hm_discovery.py` 等若被多个任务涉及，由主 agent 分配唯一写入者或按依赖串行接入。子代理需要扩大写入范围时先交回主 agent 协调，不覆盖其他代理或用户的修改。采用旧产物的任务同时承担第7节相关 purge 核对。

每个新子代理接收以下短任务包，优先给文件引用和已核对摘要，不复制完整会话或无关历史：

```text
任务：Dxx，对应 Nx；本次只完成什么。
输入：本指南相关小节、已有交付路径、原件身份与可复用范围。
约束：读取 AGENTS.md 和实施纪律；遵守冻结谓词；不得派生子代理。

```

子代理及时持久化独立完成步骤，返回简短交接；不要只把证据保存在对话或临时目录。恢复时读取任务状态及相应原件，从未完成部分接续。主 agent 针对接口和关键来源核对交付，不重复每个代理的完整调查，也不把子代理自报完成当作科学资格。

### 5.5 节省额度、升级与结束规则

- **缩小上下文与职责：** Luna 用于格式、记录整理和结果汇总；N1、N2、N3 核心直接使用 Sol/high。同配置的连续任务优先复用负责人，避免廉价模型反复试错后再全量返工。
- **问题驱动升级：** Luna 遇到跨模块语义问题时交回主 agent，用已有证据转交 Sol；Sol/high 在证据齐全后仍有具体来源一致性或恢复语义难题时，可在有效权限内调用一次 `gpt-6-astra / high` 定向咨询。咨询占用一个工作名额，默认只读，交付明确问题的判断，不重做整项实现。
- **实际配置优先：** Luna 不可用时，明确规则的任务可用 Sol/low、记录分析可用 Sol/medium，并记录替代；Sol 或所需强度不可用时，报告影响并完成可独立推进部分，不把核心证据实现静默降给 Luna。缺原件、授权、额度或环境条件不靠提升思考强度解决。
- **复核按风险和变化：** 主 agent 完成一次有范围的集成审阅；新增改动或具体失败才补做相关核对，不默认启动多模型重复评审。测试仅在用户明确授权测试或实现验证后运行，优先已有受影响用例，不默认完整 CI/HM 矩阵。
- **运行成本受既有预算约束：** 不因总体 commit 变化重跑首轮，不为 N4a 额外启动科学批次，不为排重补发候选。实施代理费用与研究生成/科学执行成本分别说明，不虚构账户额度或提供方内部调用数。
- **主 agent 持续推进：** 对就绪且已授权任务自动接续，不在每个子任务结束时询问是否继续。只在需要用户提供不可推断的信息、新额度/外传授权或不可逆范围时请求输入；保留具体待办并完成其他独立工作。

结束时主 agent 按第10节交接，列出已完成、条件式暂缓、缺证/缺授权待办和实际运行范围。N4b 暂缓或按规则暂停研究可作为有依据的结果；未完成的必要实现或因权限未启动的必要运行仍须明确保留。

### 6.2 N1：只读诊断本轮五个失败

#### 输入与输出

输入优先使用已有 native prediction/label、原生 IC/Rank IC、信号/PIT/tradability 原件、阶段 completion、receipt 和固定日历。先核对身份和完整性；原件不可取得时记录缺证，不凭报告摘要重造原结果。

从第2.3节已定位的原件继续，复用已完成核对的明确范围。比值候选与其 `abs` 版本的 IC、Rank IC 文件分别具有相同的已核对字节哈希，可共享这些文件的解析与日期统计诊断；预测是否相同、执行来源是否等价仍分别核对。相同统计文件不支持合并科学执行或追溯调整预算。[R17]

建议输出一份小型诊断表及简短说明，字段按现有格式实现，不要求新建通用诊断平台：

| 诊断字段 | 目的 |
|---|---|
| 候选、执行、阶段、来源 hash | 明确诊断对象，不把后继诊断归为旧执行当时产生的事实 |
| 失败日期及评价日历关系 | 判断是否存在缺日、重日、跨范围或统计无定义 |
| 预测/标签原始行数、配对数、有效配对数 | 区分原始缺失、对齐问题和过滤后样本不足 |
| 非有限值数量 | 分别记录预测、标签和统计值，不混同原因 |
| 预测与标签的唯一值数、方差或常数标志 | 检查模型退化和相关系数无定义 |
| membership、mapping、tradability 检查结果 | 定位 baseline-signal 的来源问题 |
| 证据支持的原因与仍未知项 | 避免把合理猜测写成根因结论 |

大型结果只在必要时集中读取。同一次诊断复用已读取且已核验的对象，保存小型汇总；不要为了不同表格重复解析相同预测文件。输出不包含凭据、无界异常原文或不必要的敏感运行信息。

#### 分类与动作

| 诊断结果 | 合理动作 | 禁止的替代做法 |
|---|---|---|
| 实现或来源绑定错误 | 最小修复，并说明受影响结论与必要后继执行 | 通过放宽统计门掩盖错误 |
| 数据或 tradability 证据不足 | 记录缺口，核对其来源及候选适用性 | 将缺证默认为可交易或自动填补 |
| 统计量因退化输出而无定义 | 进入 N2 的可评价性设计 | 直接将 NaN 改成 0 |
| 原件缺失或根因仍不明 | 保留未知和最小补证需求 | 重跑整个批次碰碰运气 |

最新失败诊断只细分若干信号阶段消息，并不证明本轮失败根因已经确定。不能仅因新代码能够生成 `SIGNAL_FINITE_WITHOUT_TRADABILITY` 标签，就给没有该证据的旧失败追溯贴上这个标签。[R9]

**完成条件：** 五个失败分别有可追溯的诊断或明确缺证说明；每项后续动作有具体理由；没有新增模型调用、重训或覆盖旧失败。

### 6.3 N2：定向修复，或建立最小后继预测证据出口

如果 N1 找到实现或数据缺陷，优先修复具体问题，不先设计新的泛化状态体系。

只有 N1 确认预测正常产出、部分日期的统计量因明确机制合法地无定义，才启动**新的探索性 profile**及证据语义。当前 `result.py` 在 IC/Rank IC 日期或有限值要求不满足时拒绝发布，比较入口又要求 `outcome.research_result_hash`；仅修改报表不能接纳这类原生输出。[R6][R18]

采用最小版本化 manifest 引用原生文件及核验结果，由新的比较适配入口消费，路径为：

```text
原生 prediction / label / IC / Rank IC 及执行来源
                      ↓
核验数据、PIT、键、日历、实际模型切分和执行身份
                      ↓
发布后继预测证据：完整日期、值或空值、状态及原因
                      ↓
按预声明的新规则生成探索性比较
```

| 证据内容 | 必须绑定或表达的事实 |
|---|---|
| 来源身份 | 候选、实际执行、输入与实现、原生文件 hash、实际模型切分及核验规则身份 |
| 预测与标签 | 原始键、配对关系、非有限值或排除项及对应规则；保留原始分母 |
| 逐日统计 | 每个预期日期的值或空值、是否有定义及原因；缺证与统计无定义分别记录 |
| 比较准入 | 可支持的分析、覆盖要求、限制及采用的评价规则 |
| 历史关系 | 后继分析或新执行的来源关系、原失败与实际退出；原 Validation、P14c 状态 |

新入口不要求旧 `ResearchResult` 已成功发布，但必须独立完成相关来源核验；不能捕获旧导出异常后直接放行。原件完整时先支持受控的后继导入，不为补证据出口重新训练；原件缺失或来源不足时保留限制。以上是待实施接口要求，不表示当前已有相应 schema。

后继规则必须在新评价前确定。允许部分日期指标时，应明确有效日期规则、覆盖要求、共同评价日期和敏感性展示；只报各自有效日期均值可能引入样本选择差异，不能与完整日期均值无条件同排。必要时并列报告共同日期结果与各自覆盖情况，但不得事后挑选最有利的日期口径。

规范化记录用空值及明确状态表达无定义日期，原始 NaN 文件保持原字节。不得自动填零、前向填充、删除后隐藏，或选择性采用 Qlib 跳过 NaN 的 summary 来绕过当前原件规则。

原 P14c、旧导出 verifier 和本轮结果保持不变。新 profile 的目的应是准确表达统计对象，不是制造更多 PASS。若使用已有数据制定了新规则，再对同一批次分析，只能标为后继回顾性分析，不能称为新的独立检验。

N2 负责证据保存、核验与消费，N4b 负责减少计算。两者共用证据接口设计；保留完整执行链时 N2 也可以完成，不要求同步实现预测专用执行器或新 Registry。

**完成条件：** 修复有诊断依据；若引入新语义，后继证据可发布、独立核验并由新比较入口读取，无需旧 Result 成功。新旧结果域明确，数据、PIT 和完整性要求保持，所有未知或无定义结果留在完整分母中。

### 6.4 N3：单 AST 顺序生成与逐次历史绑定

按首轮开放的三个窗口、算子和节点上限，结合当前 `baseline_expression_space()` 推算，共同 grammar 包含 30 个结构变体：每个窗口含 return 的两种形式、rolling_mean 的四种形式、rolling_std 和 rank 各两种形式。[R1][R13]

这是**结构变体计数**，不是 30 个独立经济假设，也不是已经运行的实验数。当前准入仍要求候选属于这一共同空间。[R5]

下一轮采用**保留单 AST 输出、仅基于此前提案历史的顺序生成**。先按 N5 明确研究决策，再冻结生成政策；本阶段不同时实施批量多 AST 响应。

当前每种方法一个固定 `GenerationRequest`，Hosted 要求一个 AST，且投影上下文集合必须与 design 冻结集合一致。因此逐次历史需要后继接口，不能只改提示词。[R4][R5][R18]

保留固定方法请求代表生成政策，在每次尝试的后继封装中绑定不可变历史快照及 hash。只增加该接口所需的版本化语义：

| 边界 | 具体决定 |
|---|---|
| 历史前缀 | 第 k 次只能使用本方法此前已持久化尝试；原响应、静态提取规则和快照可重新构建核对，不引用未来响应或最终 batch |
| 可见信息 | 仅包含政策预先允许的 AST、结构指纹及静态解析信息；不包含 IC、Validation、回测、统计失败诊断或其他研究反馈 |
| 请求与投影 | 显式区分冻结的基础上下文和本次历史，将两者绑定到 reservation、后继请求、实际投影及捕获来源 |
| 恢复与冻结 | 同一 reservation 恢复使用相同历史；再次发起生成形成新尝试并占预算。冻结时核验每次实际使用的前缀与原件 |

请求封装、投影、留存、恢复和冻结核验一起修改；复用现有原件与有界管理入口，不建设通用对话记忆服务。

| 计数 | 口径 |
|---|---|
| 实际调用数 | 记录管理侧实际发起的模型入口调用及可观察重试；提供方内部调用未知时单列未知 |
| 候选机会数 | 预先授予的提案槽位；失败、重复、修订和中断继续占用机会 |
| 科学执行数 | 记录不同候选实际执行数及执行尝试/恢复数，共享候选只执行一次并保留来源 |

三类计数分别留存，不因通常一调用对应一槽位就合并。禁止默认排重后补发直到凑齐 K 个不同候选；若将来需要补发，必须在各组预算和比较条件中事先声明。

固定顺序模板目前前五项集中在 return/abs(return) 家族。新基线可按已开放算子类别分层覆盖；随机基线预先确定有放回或无放回及 seed。不能在旧批次重抽重复项，也不能只为 LLM 提供无限修复机会。[R13]

对明确冗余的变换可以作有限报告。例如，在有效价格为正的输入域内，价格/均线比值与其绝对值相同；标准差与其绝对值也不新增信息。实际合并或复用执行前需核对定义域、缺失值及执行语义，首轮无需建设通用数学等价识别器。

比较应同时看：总生成尝试、不同结构、可分析候选、失败类别、调用与执行成本。不要只展示最优候选，也不要用成功候选数代替完整尝试分母。

**完成条件：** 每次历史可重建、可核对，恢复不会更换原上下文；调用、机会与科学执行分别计数，各组输入和预算清楚；不使用评价反馈，失败和重复完整留存。

### 6.5 N4：从已有阶段记录判断是否缩短执行链

**N4a 既有记录分析立即与 N1 并行。** 从第4.3节观察继续，按 completion、checkpoint 和调用关系列明阶段、父任务、实际运行/采用/复用状态、计时范围及重复执行或核验次数。区分 PIT、signal、模型、导出、回测变体、复现和比较核验；不能从 attempt 编号推断完整执行次数。

阶段与父任务可能重叠，不用相减填补缺失计时。若现有记录不足，在下一次本就需要运行的任务中补充轻量测量，不为性能统计额外完整重跑。

**N4b 优化按 N4a 结果选择。** 如果成本主要来自相同原件的重复核验，优先在同次核验内复用已核事实；如果大量组合变体是预测研究的主要额外成本，再评估后继窄路径。决策写清预计后续批次数、每批可省的具体工作及实现/维护成本；不以单次任务耗时长自动立项。

```text
冻结候选与执行请求
        ↓
数据、特征与时间边界核验
        ↓
实际模型切分与固定模型预测
        ↓
prediction/label、统计与来源证据
        ↓
只读探索性报告
```

需要研究组合表现时，再进入实际信号、组合规则、成本、可交易性和稳健性验证。

窄路径仍必须明确身份、预算、失败、恢复及相关 PIT 覆盖；不能因为省去了组合回测就顺带省掉特征输入检查。证据出口沿用 N2 确定的接口，复用已有 Workflow、Result 和核验组件，不新增第二套 Trainer、Registry 或回测会计引擎。

**完成条件：** N4a 给出有记录支持的成本分布、重复范围和未知项；N4b 给出实施或暂缓的理由。若实现窄路径，报告只覆盖实际完成的预测研究范围，不声称完整策略链 PASS。N4b 不是 N2 或 N5 的默认前置条件。

### 6.6 N5：先明确投入决策，再开展小规模对照

**决策设计先于 N3 定案，实际科学运行后置。** 当前问题是：LLM 能否在共同受限空间内更有效地分配有限评价机会。30 个结构的覆盖可以由简单基线实现，不同 AST 增多本身不足以证明 LLM 值得投入。

运行前在现有设计记录中确定研究问题、候选空间、模型与标签、实际切分、可见上下文、评价窗口、主指标、无定义值口径、各组生成方式、停止规则及预算。同时明确具有实际意义的质量改善幅度及可接受的额外成本，作为下一笔投入的判断依据；本指南不凭空指定 Rank IC 门槛或新额度。

第二轮仍可保持现有字段、单窗口结构和固定模型。不要同时加入多字段、多窗口、模型搜索和收益反馈，否则难以判断变化来自哪一项。

分别回答两个问题，沿用同一任务记录：

**A．生成改进是否有效？** 检查重复率、静态准入率、不同结构数和生成成本。这部分不需要科学执行；使用已获授权的生成原件进行分析，不能把静态准入称为预测可分析。若仍频繁重复，或只以更高成本实现简单基线已有的覆盖，先暂停扩大生成投入。

**B．候选质量增量是否值得投入？** 在固定候选机会预算、科学执行上限和可比较日期规则下，比较固定模型预测的主指标、可评价性及成本。计入可观察的模型、科学执行、核验和人工干预成本，未知项保留未知；共享候选执行只计一次并明确归属。

| 预声明的观察类型 | 后续投入决策 |
|---|---|
| 重复下降，但未显示质量增量且生成成本明显更高 | 当前空间优先使用便宜基线，暂停扩大 LLM 生成投入 |
| 可比较口径下出现达到预声明幅度的质量改善，额外成本可接受 | 支持下一轮有界验证，保留小样本和探索性限制 |
| 大量缺证或不可评价使质量比较不能成立 | 先解决评价问题，不给缺失分数赋零，不据此判定 LLM 无效 |
| 简单方法已充分覆盖当前空间，LLM 主要重复选择 | 调整 LLM 在当前任务中的角色；只有独立研究理由支持时才扩展表达能力 |

上述是资源决策规则，不是工程接受门或方法优越性检验。暂停投入不等于证明 LLM 无效；继续投入也不等于取得方法优越性证据。

若重用首轮已暴露时期，应继续标为回顾性探索。未见数据资格来自实际暴露历史，不来自新的 batch 名称、目录或 snapshot hash。任何用于生成或规则调节的反馈都应留存，不得把已参与选择的数据重新宣称为独立确认。

**完成条件：** 按预声明问题给出生成效果、可取得的质量比较、成本及继续/暂停/调整投入的理由。若实际启动科学批次，完整保留分母、来源、结果、失败和限制；若在生成分析后决定暂停，记录停止依据及质量增量尚未评价。工程完成不要求 LLM 胜出或全部候选可评价。

## 7. purge 修复的历史影响说明

本轮发现旧 Workflow 虽声明 `purge_trading_days=5`，实际 DatasetH 未裁切。当前修复已把裁切应用到 train/valid，并检查 forward label 边界。[R1][R7][R8]

后续应对**复用相关旧 Workflow、且依赖数据隔离声明的历史研究结果**作有限影响核对：实际使用哪些 train/valid/test 日期、label horizon 是多少、是否跨段、旧结论依赖什么证据。不能仅依据配置中存在 purge 字段就判定无影响。

此项归入采用旧预测或旧结果的具体任务，由该任务负责人记录核对范围和结论；仅采用不依赖模型训练的产物时，按其实际依赖判断。已知受影响的旧声明用后继说明限制适用范围，不启动无具体复用需求的全库历史审计。

这项工作优先是来源与声明核对，不是重新资格化：

- 旧工程流程如何执行、原件是否完整，与旧预测是否满足更强隔离条件，分别说明。
- 保留历史输入、输出、实际退出与原接受身份；需要限制某项旧声明时用后继说明，不覆盖旧文件。
- 只有某项待使用结论确实依赖受影响模型输出时，才安排必要后继计算；不默认重跑 P14/HM 全部任务。

**完成条件：** 影响范围可追溯，旧工程接受没有被无理由整体否定，旧预测也没有被误标为已执行新 purge。

## 8. 验证、复用与公开交付

### 8.1 验证应对应改变的性质

| 改动 | 优先核对的性质 | 不自动触发 |
|---|---|---|
| 格式及导航修复 | 锁定工具检查、引用正确性、状态范围 | 科学批次重跑 |
| 失败诊断 | 分类边界、原异常保留、无敏感信息泄露、失败与 checkpoint 不改写 | 新模型调用 |
| 模型切分修复 | 交易日裁切、实际 DatasetH 输入、forward-label 边界、审计绑定和恢复 | 整套 HM runtime 重资格 |
| 生成与去重改进 | 历史前缀重建、逐次投影绑定、恢复上下文一致、三类计数、冻结后不可追加及各组公平性 | 正式 P14c 或 Registry 晋级 |
| 新可评价性语义 | 原生来源、证据发布与独立核验、新比较入口、缺失原因、覆盖口径、日期一致性及旧域不变 | 追溯放宽旧导出门或重训已有完整输出 |
| 执行路径缩窄 | 必要证据完整、预算与恢复、来源身份、输出声明 | 第二训练或回测引擎 |

本文记录的已执行核对限于第2.3节；本次修订没有重复执行，也不扩大模型、科学运行或测试授权。后续在已有授权范围内完成必要验证，未执行项如实说明；不得以“局部验证”为理由声称整个版本已经验证通过。沿用当前实施纪律，避免重复审批和无关重跑。[R14]

### 8.2 复用按实际依赖，不按文件名或总体 commit 猜测

已完成且原件可取得的独立步骤应优先复用。实际依赖涉及输入、schema、policy、实现、环境和权限，不能只看代码文件是否变化。父任务失败不自动否定已完成的独立步骤，但也不能把父失败改成成功。

重新解释旧产物时，应保存后继分析及所用原件 hash。后继分析不是旧执行当时已经产生的诊断，来源采用也不是一次新的科学执行。

### 8.3 公开复核只补最小必要材料

此前远端检查时最终机器报告公开读取返回404，第2.3节后继本地评估已确认指定原件存在并核对报告哈希；本次修订未重新检查公开可读性。可在不披露受限数据的前提下，保存小型结果摘要和来源关系：生成批次及候选映射、最终报告身份、实际执行源码与公开提交关系、失败摘要、检查范围和未知项。N1、N4a 使用已有受控原件，不以补上传为启动前提。

优先复用已有报告格式，不为公开复核新增完整证据平台。不能把手工摘要冒充原报告原字节，也不能上传凭据或不具备公开权限的数据。无法公开的原件明确写为受控保存，并说明可复核到什么程度。

| sealed confirmation 或实盘晋级 | 当前探索报告不授予这些结论 | 独立满足各自数据、执行、统计与权限要求 |

## 10. 下一阶段整体完成条件

下一阶段建议命名为：**有界研究可评价性与生成多样性改进**。

完成时给出短交接：当前代码检查状态；五个失败的归因或缺证；按需建立的后继预测证据及比较入口；逐次历史绑定和三类计数；实际生成或科学运行结果、成本、复用范围及限制；依据预声明规则作出的继续、暂停或调整 LLM 投入决定。生成分析后暂停时，明确预测质量增量仍未评价，不为关闭任务强行启动科学批次。

不得把以下事项作为制造“完成”的手段：修改旧失败为成功、放宽旧阈值、删除 NaN 日期而隐藏、把缺失分数记零、只报告最佳候选、把预算单位当秒数、将已暴露数据改名为未见样本，或为关闭任务无理由重跑全部历史流程。

**最终判断标准：工程改进是否使候选质量与成本能够可靠比较，并支持有依据的研究投入决策。**
