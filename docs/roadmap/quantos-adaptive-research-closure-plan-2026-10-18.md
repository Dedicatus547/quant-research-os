## 1. 下一步究竟要补什么

目标不变：固定数据、工具和预算内，提出方案、执行检查、根据结果决定下一步，必要时生成新方案，最终交付有证据的结论或有理由地停止。

AR0–AR5 已完成实现及定向离线模拟；首次真实运行完成了有理由的 STOP。当前主要缺口是**有信息价值的具体任务、真实生成/科学/反馈链的证据，以及可复用的自动收尾**。
后续只补两个小的工程环节：准备阶段的历史事实与来源核验、运行后的证据闭合与能力分项报告。主循环、SDK transport、Qlib、科学门和预算框架继续复用。

首个目标是取得一条真实的“新方案 → 实际检查 → 本任务结果 → 后继决策 → 交付”路径。
后继决定可以 STOP，科学结果可以 REJECT；不要求盈利。后继修订若未发生，就单独保留该分支缺证。
跨宿主、无限轮次、全部故障自动恢复、长期质量改善和 P14d-C 不纳入此次最小交付。

## 3. 先形成一个值得检查的任务

N0 先从小型原件找一个尚未回答的问题，给出**一张任务说明**，不启动新的 SDK 或科学任务。
必须同时写明：已知事实及原件字段、未知问题、相反解释、一次检查能区分什么、需要哪些可观测量、什么结果足以停止、什么结果才支持下一方案。
保留全部相关负面和缺失证据；不得删掉暂停意见诱导模型生成，也不预先填写模型最终表达式或第二步动作。

优先调查方向（**暂定问题，尚未通过任务准入，不是已成立的研究假设**）：

> 在固定数据、模型、交易与成本政策下，既有允许表达式中的时间窗口/平滑结构，是否留下了尚未检查、
> 可以帮助解释高换手率的对照问题？有无与原结果可比较的基线，以及足以区别两种解释的检查？

依据是两份已有 Validation 的 G5 记录了约 58–60 的年化换手率，高于冻结阈值 12；
原件定位见[科学明细索引](../../artifacts/agent-runtime-bounded-20261017/candidate-29fef56-01/operator-run-01/scientific-report-detail.json)。
这只说明有现象需要解释，**不证明平滑会降低换手率，也不证明问题来自因子而非交易政策**。
要核对数据、时期、学习器、策略、成本及指标口径的依赖，才可采用历史对照；相同指标名称不能代替可比性。

若已有 G7 参数扰动或其他保留结果已回答该问题，直接采用并放弃新执行；优先检查已有小型结果，不重算大型预测。
若对照需要两次新的执行，在任务说明中明确成本及两次结果各自用途；第二次仍由反馈后的决策决定，不能预定必须执行。
需要新字段、改变交易规则、扩大 grammar、开放 sealed 或追加科学次数才能回答时，该题不进入本轮。

另一个可核对的缺证线索是 B2 报告的 `combination_minus_best_constituent=null`，语义为组成部分不可用；
该报告不能当作组合效果为零。是否能用已有兼容来源回答，需核对[原 B2 报告](../../artifacts/hosted-evidence/a1-b2-20261012-01/b2/prediction-followup-r6/report-bf465a3701b3a697220b059eea2f14088363173964f7a53d76796b1a3844c0b8.json)。
本轮最终只选一个问题；若会引入新的预测比较流程，暂缓该题，不另开工作线。

没有合格问题时，交付“当前范围无足够理由启动新实验”的具体缺证说明，仍完成不依赖该问题的工程改进。
这不能记为完整目标达成，但能避免无依据地循环烧额度。将来需要扩大数据/工具时，另给具体变更和成本再决定。

## 4. N0–N4 开发和验证顺序

| 任务 | 最小改动与复用 | 依赖/负责人 | 完成标准与停止条件 |
|---|---|---|---|
| N0：任务与事实说明 | 只读旧 STOP、两份 Validation、相关扰动/比较原件和已试结构；生成一张任务说明及字段来源表。已有研究若已回答则直接采用 | 首先；Sol 主导，Astra / High 做一次问题与可比性审查 | 明确为什么这次能增加信息、何时停止；不能成立就不准备真实执行，不强编假设 |
| N1：历史证据到输入的闭合 | 在现有准备器增加显式后继 recipe 的事实提取/检查；所有读取的 batch 和模型可引用 hash 都须解析到核验过的原件。字段白名单投影为有限 context，推断标为推断 | 接口确定后；Sol / High；可与 N2 并行 | 改指标、换来源、漏 batch pin、把 null 改 0 或把执行失败改科学结论均被拒绝；实际 prompt 与核验投影相同 |
| N2：自动只读收尾 | 复用已有 capture 校验、事件/预算逻辑和审计检查，给现有 CLI 加薄的收尾入口。收集独立退出并核对 SDK/科学/receipt 后输出报告及库存 | Sol / High；文案由 Sol / Medium；与 N1 分文件 | 同一原件反复核对无新增调用、执行或 authority 事件；缺证不能宣布已覆盖；未知用量保留 unknown，逐项报告真实能力 |
| N3：局部验证与具体运行包 | 复用 61 个已有用例及已接受依赖；仅补 N1/N2 的反例。用已终态 STOP 原件验证新报告只认 STOP；交付固定候选提交和新任务包 | N1+N2；Sol / High 集成，有限 Astra 边界复审 | 全部必需离线工作结束，包内实际路径/命令/外发/预算齐全；此时仍标真实组合待验证。不启动旧 launcher |
| N4：一次真实任务与逐项接受 | 新授权后复用现有 run/namespace/receipt 流程；一次启动到终态，自动执行 N2 收尾。若普通代码缺陷出现，保存原失败并交回开发线 | N0 合格+N3+具体运行授权；运行会话 Sol / Medium | 按第 6 节判定分支。首次 STOP 仍有效但不算完整链；UNKNOWN 不重发，不为获得生成结果反复换模型/改措辞重跑 |

N1 更小做法是手工复核一次摘要；它可支持一次任务，但每次仍依赖操作员维护事实，不能解决重复使用时的引用缺口。
实现优先采用新 recipe 的小型事实对象，生成现有 spec 的 context 字符串；若无需改 runtime schema，就不新建一整套任务契约。
事实抽取只支持本批实际使用的原件类型及少量字段，不建设通用文档理解或知识库。

N2 更小做法是继续任务专用审计脚本；上次已出现人工整理和重做管理审计，因此值得把稳定部分提取为一个薄入口。
该入口应读取事实而不调用会补写 response 的 `complete()`；如需共享其核验，最小抽出只读核验部分，保持旧写入行为。
只读收尾不等于 `reconcile`：缺 receipt 时先报告缺证；有授权的对账完成后，再读取新的快照。不得伪造进程退出。
正式输出写入新的、排除在输入库存之外的持久审计目录；等被采集日志关闭后生成最终库存，避免摘要自引用或活动文件哈希漂移。
保留旧审计失败和冻结扫描器，不靠放宽秘密检查完成收尾。

N3 只因实际代码/依赖变化增加验证；若某项检查已有等价实现和可采用原件，删减对应开发任务并记录原因。
父总账、冻结子任务、取消/TTL、UNKNOWN 和科学执行引擎不预设改动。若观察到具体故障，再局部定位。

## 6. 什么才算本轮达到目标

| 实际发生的路径 | 可以认定 | 仍不能认定 |
|---|---|---|
| 首次 STOP | 本任务正常停止、预算/交付路径 | 新提案执行、本任务反馈后决策 |
| 新方案产生，但执行失败或来源不完整 | 真实提案；按原件观察到的失败/安全停止 | 完整科学检查已完成，或根据有效科学结果作出判断 |
| 新方案实际检查完成，收到结果后 STOP | 本任务的真实生成—检查—反馈—决策—交付路径；科学 REJECT 可接受 | 反馈后生成修订、长期改善、未实际执行的科学分支 |
| 新方案检查后提出修订并执行、最终交付 | 上述路径，加本次真实修订分支 | 因果质量改善、长期可靠、盈利或全部未来任务有效 |

最低真实闭环要求：模型生成至少一个未在该任务已知历史中出现的新结构；程序实际检查并获得完整来源的结果；
同一任务的结果进入第二次实际请求；模型说明据哪些结果继续或停止，且行为与说明一致；程序完成记录和预算交付。
如果科学在 PIT 硬拒绝等门提前停止，就明确哪些阶段已观察，不能把未运行的 Qlib/回测阶段也标通过。
后继修订能力已有离线接线证明；没有真实修订时仍需单列缺证，不能把“完整链观察”扩大成所有分支均已真实证明。

为减少事后解释，任务说明预先写明哪些观测会支持何种行动，以及哪些不足以支持判断；这不是强制第二次动作。
单次真实模型引用反馈、作出合理决定，只支持观察到的反馈使用，不独自证明反馈导致更好决策。
反馈因果改善需要独立设计对照，当前不另开模型效果实验。

允许用固定候选/预写响应补离线接线证据，但不能用它填补真实模型生成的验收项。
没有真实生成时，不通过禁用 STOP、换措辞抽签、换更强模型、增加机会或改变科学阈值来把任务刷成成功。

## 7. 自动化、预算与两线

用户只需要一个开发主会话和随后一个运行会话。开发主会话自动做 N0–N3、普通问题修复、证据整理、局部验证和实际命令生成；
每个独立完成步骤保存持久 checkpoint。N1/N2 可在文件归属及资源许可时并行；同一任务的 SDK→科学→反馈、恢复/结算串行。
确定性程序负责提取事实、准入、去重、报价、执行、对账和最终报告；不额外调用模型总结日志或修 JSON。

建议新授权包仍最多 **2 次 SDK 决策、2 个新候选、2 次科学执行，自动 SDK retry/UNKNOWN 重发/科学 restart 均 0**。
实际只需 1 次科学后 STOP 就不使用第二次科学；第二次 SDK 是读取反馈后的决策，不是自动重试或总结调用。
失败/非法回答同样占 SDK 机会；科学机会不能因失败退款。旧 `package-01` 的剩余预算不续用。
若保持原冻结形状，旧报价 17/18 policy units、总 cap 36、3 小时期限和 5 GiB 增长估算可以按依赖核对后采用；
输入、工作量、环境或并发变化时重新报价。真实宿主卷余量、共享租约和安全收尾空间在启动前核对。
policy units 不是秒、token 或现金；订阅余额未知就如实记录，不能承诺精确费用上限。

真实调用仅因新的事实输入/新任务和未观察的科学闭环确有缺证而提出；不额外开“探针调用”后再重置次数。
已有授权若明确覆盖同一新包就直接采用；若不覆盖，开发线先完成包并一次性列明问题、版本、命令、数据外发范围、预算及停止条件，再申请批准。
运行时不逐轮询问；来源不明、UNKNOWN、预算/容量/权限边界或新费用超出范围时安全停止。

开发起点为 `ca1b603` 或核对后的后继，新建开发 worktree；不改 `5235445`、`29fef56` 保留工作区和历史证据。
开发会话先交付本地提交和新运行包；新的候选提交固定后再运行，运行会话不现场修源码、升级 SDK 或改变 profile。
故障交接带原件、实际退出、占用额度和可复用完成步骤；修复只在开发线进行，补证只覆盖实际变化。
推送、合并、部署依当次授权处理；计划本身不执行这些动作，不开第三条长期工作线。

## 8. 模型与思考强度

以下是本项目分工建议，依据 [OpenAI 官方模型指南](https://learn.chatgpt.com/docs/models)核对模型定位，不是本仓效果实验结果。
模型/强度应由客户端或受支持子代理工具实际设置，提示词中的名称不会自行切换配置。

| 工作 | 模型/强度 | 使用方式 |
|---|---|---|
| 开发主会话、N1/N2 核心实现、N3 集成 | **GPT-6.1 Sol / High** | 持续推进与修复，保持任务和源码上下文 |
| N0 问题是否有信息价值、对照可比性；一次关键验收复审 | **GPT-6 Astra / High** | 两个有限任务；仅具体难题仍未解决才升 Extra High。不设常驻专家团 |
| 原件字段提取、报告模板和明确的 CLI 文档 | **GPT-6.1 Sol / Medium** | 涉及来源权威/预算/恢复转 High；能用程序完成的整理不调用研究模型 |
| 路径清单、链接和操作说明校对 | **GPT-6 Luna / High**，可选 | 限明确可机械核对的任务，不裁定科学结论 |
| N4 运行操作会话 | **GPT-6.1 Sol / Medium** | 按固定包自动启动、观察和交付，不现场开发 |
| runtime 的实际研究决策 | **GPT-6.1 Sol / Medium**，保持现有 SDK/profile | 首次 STOP 不是模型能力不足证据；不因停止而升级。更换模型须独立说明依赖与预算 |

不默认 Max/Ultra。用户发送下方开发提示词后，最多两个临时子任务并行；共享 authority 由主会话管理。
若不能指定子代理模型或账户没有 Astra/Luna，由 Sol / High 继续并记录限制，不为可选模型停工，不虚报模型身份。
开发聊天/子代理的消耗与正式 SDK 研究次数分别记录；“研究调用 0”不表示开发会话不消耗订阅。

## 9. 初学者实际操作

1. 在 Codex 打开 `/home/zjw/quant-research-os`，实际选择 **GPT-6.1 Sol / High**。
2. 复制 A；保持一个主会话，让它连续完成 N0–N3，不重新执行旧 AR0–AR5 提示词。
3. 收到交付时，只需看：具体问题是什么、为什么值得做、最大消耗是多少、哪些结果会停止。若没有合格问题，不批准盲目实跑。
4. 同意具体新包后，新开 **GPT-6.1 Sol / Medium**，粘贴开发线已经填好全部路径的 B 提示词。无需自己找哈希或拼命令。
5. 看最终分项表：只有真实新方案、实际科学检查、本任务反馈后决策均有原件，才认定观察到了该闭环。

### A：开发主会话

```text
请执行 /home/zjw/quant-research-os/docs/roadmap/
quantos-adaptive-research-closure-plan-2026-10-18.md 的 N0–N3。
先读 AGENTS.md、实施约定、现状和首次 STOP 原件。AR0–AR5 已完成，不重新实现。

我授权本轮必要实现、定向离线验证、独立 worktree 和开发分支本地提交；
不授权真实 SDK 研究调用、科学任务、采集、部署、推送或扩大现有数据/工具范围。
请连续完成任务设计、最小代码改动、局部验证、普通故障修复和运行包，不逐步询问是否继续。
持久保存 checkpoint，复用已完成的源身份和验证；不要重复运行大文件/科学来填报告。

主会话 GPT-6.1 Sol / High。我允许有限子代理分工：Astra / High 审查 N0 的问题与对照，
以及 N3 的关键证据边界；Sol / Medium 做独立投影/报告接线；Luna / High 可校对清单。
最多两个子任务并行，明确文件归属；无对应工具或模型时由主会话继续，不因此停工。

N0 找一个现有范围内尚未被原件回答、实验结果能影响下一步的具体问题。
保留负面及缺失证据，不预写 runtime 的最终候选或强迫第二次继续。
没有合格问题就交付原因，并继续完成不依赖它的 N1/N2；不要编造研究价值或启动试探调用。
N1 闭合历史事实/字段/来源与实际模型输入；N2 做只读、零调用的自动收尾。
旧规则、失败、科学状态和 STOP 权利保持不变。新方案/科学/反馈后决策逐项留证，
首次 STOP 不得被报告为完整闭环，未知副作用不能重发。

最终交付固定本地提交、采用和新增的验证原件、任务说明、未解决事项，
以及填好实际路径/命令/环境/外发范围/额度的新运行包和 B 提示词。
最多2次SDK、2个新候选、2次科学，retry/reissue/restart为0；
policy units、TTL和宿主空间按实际依赖核对，不借用旧 package-01 余额。
具体包完成后才申请真实运行授权；本轮保持离线。
```

### B：运行会话模板

开发会话应把实际新包路径、提交、具体额度、命令及用户批准原文填入完整提示词；以下模板现在不执行。

```text
请在固定运行 worktree 按本消息附带、我已批准的新运行包执行 N4。
核对 AGENTS.md、实施约定、版本/环境/输入/额度，使用包内实际命令和独立持久输出。
一次启动后自动完成研究和只读收尾，普通进度不逐轮询问。
模型保留首次或反馈后 STOP 权利；不要为验收强迫生成、修改阈值、换模型重试或追加预算。
UNKNOWN 不重发，科学不重启，完整原件只按授权对账；运行中不修源码或升级依赖。
真实异常保存原件、实际退出和占用额度，交回开发线。
最后给出问题的回答或停止理由，以及真实提案、科学各阶段、本任务反馈后决策、
修订和停止的分项原件。区分完整链已观察、仅STOP、部分路径和缺证；不自动授予资格。
```

会话中断时可复制：

```text
继续当前 N0–N4 后继计划。先读 checkpoint、Git 状态和已有原件，沿用此前授权范围。
只做未完成或依赖确已变化的部分，不重发 UNKNOWN、不重复已完成科学、不重置预算。
若只授权离线开发，继续保持离线。说明恢复点后继续工作。
```
