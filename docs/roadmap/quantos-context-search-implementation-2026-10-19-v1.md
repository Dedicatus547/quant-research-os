当前最有价值的工作，是核对两次真实首次 STOP 的实际输入、停止理由与可用动作，并据此判断是否需要调整上下文。研究 SDK 已经逐请求创建新的临时会话，不需要再增加一个同义的 flush 开关。历史事实投影和自动只读收尾也已经实现，应复用现有入口，只修复有证据的缺陷。

近期默认交付为一次有针对性的只读诊断。上下文修正、模型效果对照和长期分支搜索各有独立进入条件，不构成必须全部执行的流水线。合理的 STOP、确认无需修改，以及确认当前证据不足，均可成为有效交付。

## 1 采用结论

| 建议 | 当前优先级 | 采用理由 |
|---|---|---|
| 核对实际 prompt 与 STOP 的理由 | 立即开展本地只读审阅 | 先确定是否存在需要修复的问题 |
| 改善事实与历史判断的呈现 | 发现具体输入问题后实施 | 可复用现有投影，改动范围小 |
| 比较不同上下文投影策略 | 有可检验假设后单独设计 | 需要实际模型观察，离线检查不能代替 |
| 在复杂开发任务中进行独立探索 | 遇到具体停滞任务时采用 | 更接近论文的长会话和累积工作区 |
| 给研究 runtime 增加周期清空会话 | 暂不实施 | 当前每次决策已经使用新 thread |
| 引入多分支长期研究调度 | 后续条件满足再评估 | 当前预算和轨迹证据不足 |

应延续的架构方向是：确定性内核保存事实、身份、资源与评估；Agent 根据证据解释结果并选择行动；harness 提供清晰的信息和动作边界。研究成果应当累积，研究解释应当允许重新审视。

本建议不会要求重新实现 AR0–AR5、N1/N2、Qlib、科学门或预算总账。实施前检查是否已有等价能力；已有能力满足需要时，直接采用并从工作清单删除重复任务。

## 2 论文依据及迁移边界

论文周期性复制已有工作区，以新的聊天上下文启动多个探索分支，再按外部评分选择后续方向。主实验的归一化均值为：单链 0.47、best-of-4 0.54、完整方法 0.78；11 任务消融中，单链、仅清上下文、仅分叉、完整方法依次为 0.45、0.55、0.57、0.71。两组实验不能跨行直接比较。[R1]

这些结果支持将状态重建与预算分配作为研究变量，但不能直接转译成 QuantOS 的收益或额度改善。论文 credits 按模型 token 计量，求解器与训练作业不消耗这部分 credits；其任务、交互形态与当前研究 SDK 不同。[R1]

本项目应区分两项假设：

1. **历史解释影响决策的假设**：新会话仍可能因显式 prompt 中的旧判断而沿用原来的方向。
2. **分支搜索改善预算利用的假设**：在可评价的多轮研究中，独立探索并选择后续可能优于持续投入一条轨迹。

当前源码使第一项具有诊断价值；现有运行证据尚不足以支持第二项已经成为项目瓶颈。改善投影不等于复现论文，也不等于证明 Agent 已逃离某个“思路盆地”。

### 4.2 分清停止发生的层次

每包分别回答：

1. 运行协议是否正常结束，最终原因码是什么？
2. 模型是否明确选择 STOP，原始理由是什么？
3. 理由中哪些是原始观测，哪些是既有模型意见，哪些是当前推断？
4. 输入证据能支持多大范围的停止结论？
5. 当前约束下是否仍存在可执行且有信息价值的动作？

必须区分 MODEL_STOP、DUPLICATE_AST、STATIC_ADMISSION_REJECTED 和 PARENT_BUDGET_EXHAUSTED。返回 STOP 不代表预算真的耗尽、全部结构失败或执行过程异常。[R7]

理由审查尤其注意：

- 少量已试结构失败，不能自动推出全部允许结构失败。
- FAILED 或 NOT_EVALUATED 不能改写成候选已经被完整科学检查否定。
- null 不能改写成零。
- 旧 Agent 建议暂停，不能仅凭来源哈希正确就当作科学结论。
- 未试过一个结构，不足以证明值得为它支付新实验成本。
- 科学 REJECT 可以是有用研究结果，合法 STOP 也可以是正确行动。

**完成标准**：给出“原始陈述—来源—可支持的结论范围—尚存解释”的简短原因链；证据不足时保留不确定，不强行选择一个根因。

### 4.3 检查模型是否获得足够的信息

将实际 prompt 中影响行动的内容分成三类：

| 内容类别 | 例子 | 检查方式 |
|---|---|---|
| 必须保留的事实与限制 | 实际指标、拒绝原因、缺失、预算、字段和 grammar | 核对原件及当前请求 |
| 需要保留定义的研究假说 | 正在检验的结构、对照目的、原假说 | 确认删改不会改变研究对象 |
| 可重新审视的历史判断 | 旧 rationale、行动建议、未经验证的原因解释 | 核对是否实际进入输入，以及如何标记 |

只在实际输入中存在相关内容时，才讨论它可能带来的影响。尤其两包均为首轮 STOP：源码支持“后继投影包含旧判断”，并不能证明该字段进入了这次首轮请求。

另行核对已见结构 hash 是否有可读表达式或必要说明。当前 prompt 构造本身不等于提供了完整的未试目录；模型未必能够仅凭 opaque hash 判断哪些对照已经做过。若需要补充，可从已经绑定的历史批次和现有 grammar 生成小型可读映射，不启动科学评估。

覆盖统计必须限定为“这些实际核对批次中已出现的结构”，不能把它当作整个项目的全部搜索历史，也不能用旧讨论中的结构数代替最新统计。

**完成标准**：能指出一个具体的信息缺口或呈现问题；没有发现时明确无需修改。不能仅因模型 STOP 就认定 prompt 不足。

### 4.4 交付诊断结论

默认只需要一个简短诊断文档；已有机器输出可作为引用。只有确实新增程序化投影时，才增加对应小型数据文件，不建立新的报告层级。

建议文件名为 context-stop-diagnosis-2026-10-19.md；采用仓库既有目录约定，避免覆盖旧阶段文档和原件。内容包括：

- 实际源码基线与已采用证据；
- 每包的输入、停止类型、原始理由与支持范围；
- 是否存在与本建议相关的实际上下文问题；
- 可行动作和研究信息价值的判断；
- 下一步选择：无需修改、最小修复、准备上下文对照，或继续保留证据缺口。

上述选择只是本次诊断结论，不新增运行时状态枚举，也不改变科学状态或资格。

## 5 条件性最小修复

只有第 4 节识别出具体问题时，才实施本节。实现范围由实际缺陷决定，不预设必须新增模块或配置项。

| 发现 | 适当处理 | 不应据此推导 |
|---|---|---|
| 停止理由与证据、预算和可行动作相符 | 采用停止结论，结束本轮 | 不需要为提高生成率修 prompt |
| 原件事实投影错误、缺字段或状态含义失真 | 局部修复投影或绑定，并验证实际反例 | 不能重分类旧科学结果 |
| 只有 hash，缺少判断对照所必需的结构说明 | 从已绑定来源补可读映射，保持体积和范围约束 | 不能声称已评估未试结构 |
| 旧意见被呈现为已证实结论 | 分清事实和意见的身份，给出前后差异 | 不能宣称修复后模型效果必然提高 |
| 问题需要当前范围之外的数据或动作 | 交付当前任务不适用的理由 | 不自动扩大 grammar、工具或预算 |
| 看起来可能有锚定，但没有可核对输入证据 | 保留假设，暂不改代码 | 不以想象的机制解释真实 STOP |

必要的改动优先落在现有 project_history、准备流程或 _request 的相应入口。能通过新任务的合规 recipe 表达，就不为单次任务增加全局模式；确需契约变更时，先明确新旧语义及适用身份，不改变旧包。

验证只覆盖实际变化及具体风险：

- 事实与类型仍对应原件；
- null、REJECT、FAILED、NOT_EVALUATED 仍保留；
- 引用、请求和反馈不串任务；
- 必要假说、权限、预算及曝光信息仍完整；
- 已终态任务不会因新投影被重新执行。

已有测试满足这些风险时采用原有证据；修复真实缺陷时增加能够捕获该缺陷的测试。无代码修改时，不为了交付新增测试、格式化全仓或重跑完整资格矩阵。

**完成标准**：说明改动解决的具体问题、前后输入差异、最小验证以及剩余限制。正确生成新的 prompt 仅证明实现性质，不能证明研究行为变好。

## 6 条件性上下文对照

### 6.1 进入条件

只有同时满足以下条件，才准备实际模型对照：

- 原件显示存在与假设相关的历史解释或呈现方式；
- 有一个尚未回答且能通过对照区分的问题；
- 两种输入能保持相同的研究对象、必要事实、动作范围和主要预算；
- 结果会改变是否采用该投影策略的决定。

如果实际输入不包含所怀疑的旧解释，应说明该机制不能解释当前 STOP。若研究关注的是“真实反馈后的解释如何影响下一步”，则必须有真实反馈状态；不能用两个不同任务的首轮请求冒充该状态。构造的离线夹具只能证明接线。

### 6.2 对照设计

初次只选择一个明确变化，不同时更换模型、思考强度、研究问题、数据范围或多个提示策略。

| 条件 | 说明 |
|---|---|
| A 当前策略 | 采用经核对的现有上下文构造 |
| B 待验证策略 | 维持相同必要事实和限制，仅调整预先选定的历史意见呈现方式 |
| 会话形态 | 两组都沿用当前新 thread，不添加额外 flush |
| 评估对象 | 对同类已验证决策状态的判断质量和成本 |
| 推论范围 | 输入敏感性或有限任务效果，不等于复现长期 Fork-and-Flush |

B 可以将历史观测与旧行动建议清楚分开，并明确后者可根据当前证据重新判断。若选择“省略非必要旧解释”作为变量，必须先证明它不是研究对象的必要定义，保留完整原件和所有相关负面事实，并在新对照设计中明确声明。

不能静默删掉暂停依据来诱导生成；也不能反复换措辞直到出现 PROPOSE。A/B 两组应预先固定，查看结果后的改版属于新的开发尝试，继续留账。

### 6.3 观察什么

主要判断是：在同等任务和资源条件下，是否作出更有证据支持的行动选择，或以更低成本达到相近质量。预先按任务写出哪些已知情形支持停止、哪些支持进一步检查，避免事后凭“看起来更积极”评分。

可记录：

- 对原始证据、缺失和适用范围的理解是否正确；
- 建议动作是否可执行，是否能区分当前未决问题；
- 需要停止时是否有充分理由；
- 若处于真实反馈后状态，是否正确使用该反馈；
- 调用、输入输出 token、耗时、科学执行及人工核查成本。

PROPOSE 比例、新结构数和重复率仅作诊断。不能用另一个 LLM 的偏好评分单独宣布改善，也不能把一两次差异包装成统计显著或普遍能力提升。

### 6.4 如何形成可运行包

离线阶段先完成输入构造、来源映射、语义差异和评价规则。准备包必须填明实际任务身份、模型和环境、调用次数、数据外发范围、总成本边界、终止条件及输出位置。

运行包还须说明如何在现有身份和预算规则内，从同一已固定的预决策状态形成 A/B 两个独立请求，并预先划分每组预算与全局上限。两组原件分别绑定，全部实际费用和曝光共同留账；不得将 A 新产生的反馈、已见结构或余额变化自动作为 B 的初始输入，也不能重用旧请求身份或假定预算恢复。现有入口不能满足时，先交付这个接入缺口，不改写旧包或直调 SDK。

不在本文件中预设增加现有 2 次 SDK 或 36 policy units 的上限。对照中的新模型调用即使不启动 Qlib，也属于新的实际调用，必须计入相应范围；不能伪装成免费回放或隐藏在“总结”中。

使用已授权且确实覆盖该任务的范围即可，不重复请求同一授权。没有覆盖时，先完成可核对的运行包，再在实际执行前一次性取得所需批准。不得通过直调 adapter、新建 task 名称或更换目录绕过原有预算与执行边界。

**采用标准**：只有观察到与预先目标一致的质量或成本改善，才考虑采用新的默认投影。若结果接近、只有生成率变化，或成本更高而质量无明确收益，保留当前方案并结束该项改造。

## 7 长期分支搜索的后续条件

当前两次 SDK 机会若平均分给两个分支，每支只剩一次调用，无法让每支完成“提案—实际检查—根据反馈再决策”。这主要是首轮多次采样，不足以检验论文的持续研究与再次分叉机制。

未来只有出现以下实际需求，才讨论分支调度：

- 已观察到可运行且有价值的多轮研究；
- 同条件轨迹会探索不同方向，且差异有利用价值；
- 单链继续的边际信息价值降低；
- 每支有足够预算获得有意义的反馈；
- 仍有合法可探索空间和可信比较目标。

到时优先采用小规模、固定且可解释的策略。先比较连续研究与有限分支，并保留规则选择或无重复随机覆盖基线。不要因为论文使用多个分支，就默认开发树状调度器、动态停滞检测、常驻 worker 池、自动 K 调优或通用记忆平台。

将整个搜索过程作为评估对象。新的 thread 不会使数据重新变成未见样本；确定性回测和 PIT 正确性也不自动消除自适应选择偏差。[R12][R13]

需要保持：

- 分支选择使用的数据明确属于开发和探索；
- 最终评价的方法、指标和数据角色在看结果前确定；
- 未胜出分支可以停止执行，但全部实际尝试、费用和曝光留账；
- 共享祖先和市场样本的分支不作为独立金融证据；
- singleton 子任务不自动授予父搜索整体多重检验保证。

这些要求优先落实在现有 Ledger、预算和记录中，不为本建议新增一套统计平台。数据不足或评价不可信时，分叉无法修复该问题。

## 8 开发长会话中的独立探索

这部分针对使用 Codex 开发 QuantOS 的工作流，不属于研究 runtime 的能力资格，也不消耗或继承研究包的科学预算。

在复杂故障、实现方案或性能优化已经反复局部修改而缺乏进展时，可以从同一个固定源码状态与事实包，让两个独立新会话短期探索。共用目标、复现材料、必要约束和预先约定的验收方式，分别保存改动。

比较依据应是可复现的工程结果、原因解释是否成立、改动范围和必要验证。采用一个可审阅的后续方案，不自动合并互不兼容的结果，不以文本说服力代替工程证据。

原先主线与 FR-03 worktree 分别处理不同需求，属于并行分工；同一问题的多解探索是另一种用法。两者无需统一成新的常驻协调框架。

只有存在具体停滞问题时才采用这一做法，避免每个普通任务都复制两遍。开发会话成本单独记录，不能用“研究 SDK 调用为零”表示开发工作没有额度消耗。

|---|---|---|
| 只读诊断后无需修改 | 一份简短诊断及原件引用 | 当前未发现需要新增机制的问题 |
| 发现并修复输入或实现缺陷 | 最小补丁、诊断、实际差异和定向验证 | 具体缺陷已修复 |
| 仅完成上下文对照准备 | 已绑定输入、比较变量、评价规则和具体预算 | 对照已具备审阅条件 |
| 完成获授权的模型对照 | 两组实际输入输出、成本和预定评价 | 仅按观察范围报告输入或任务效果 |
| 尚缺原件或真实反馈状态 | 已完成部分和精确缺口 | 保留不确定，不声称因果或完整闭环 |

统一的交付要求：

1. 指明实际采用的源码提交和证据身份，不用旧基线代替当前代码。
2. 区分源码性质、发布记录陈述、实际原件观察和推断。
3. 解释为什么需要每项新增工作；已有等价能力直接采用。
4. 保持历史科学结果、失败、终态任务和资格的原有身份。
5. 不以代码量、候选数、分支数或 STOP 变少作为成功标准。
6. 本轮没有适用的代码变更或实验动机时，明确结束，不为完成清单扩建设施。
