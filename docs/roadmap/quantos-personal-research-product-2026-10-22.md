# 自用量化研究产品：Codex 实施计划

日期：2026-10-22。状态：**已启动并交付有限本地实现/安装/受阻研究准备；真实市场适配与连续前瞻账户仍有缺口**。
配套 [启动指令](quantos-personal-research-product-start-2026-10-22.txt)。
本计划替代“逐项复刻用户手动交易动作”和“仅交付选股提醒”的近期方向；不修改历史科学结论、冻结合同或旧授权。
本计划编写时仅规划；本轮用户已发送启动指令，开发、定向验证及本地安装授权已生效。
实际采用范围见[使用说明](../guides/personal-research-product.md)与
`artifacts/personal-research-product-20261022/run-01/handoff.md`；工程演练不等于真实策略资格。

## 1. 产品目标与最终需求

目标用户是项目所有者本人。产品是**研究方向 → 模型设计策略 → 确定性执行与比较 → 解释结果 → 条件性前瞻模拟**的量化研究助手。
通过本机任意能访问相同运行环境的 Codex 会话调用，不要求用户切到仓库、记路径、填哈希或手工串联脚本。
量价与公告共用任务入口、资料查找、持久历史和结果解释，底层仍使用各自受控流程。
不是自动下单产品，也不以网页、跨机部署、AI-vs-人比赛或获得盈利策略作为首版工程完成条件。

用户提供方向、市场范围和资源边界；模型自主选择成熟方法、参数、买卖规则和对照，承担解释与验证义务。
不要反复要求用户指定均线周期、量比阈值或每个实现参数。只有改变目标、数据来源偏好、费用/外传范围或重大取舍时才集中提问，并给建议及理由。

### 首个真实研究 brief

> 研究 A 股主板的短线趋势机会。结合市场环境、同花顺板块强弱、个股趋势与成交活跃程度，并利用公开公司信息识别风险。
> 收盘后形成研究/候选判断，次日开始交易；通常关注几天内的机会，强势持续时可以持有更久。
> 模型自行生成可执行策略，扣除成本后与适当的市场基准、简单经典策略和随机对照比较，解释是否值得进一步模拟。

需求分类：

| 类型 | 内容 |
|---|---|
| 已确认范围 | A股主板；本机Codex；自用；量价/公告统一；用户给方向、模型设计策略 |
| 已确认偏好 | 同花顺板块口径；收盘后选股、次日买入；短线且无固定3天持有上限 |
| 启发而非强制规则 | 跌破分时均线后第一波反弹未回此前当日高点、后继已完成5分钟K线收阴退出；尾盘成交量约昨日两倍退出；股东人数/知名机构/利空检查 |
| 模型自主决定 | 具体指数、趋势定义、参数、买卖方式、持仓与退出、是否采用上述启发、经典对照选择 |
| 需要确认的实质变化 | 同花顺行业/概念口径确有歧义时集中确认；缺同花顺历史数据而改用申万；全主板改成沪深300；要求盘中规则却改日频；新增数据采购或额外研究调用 |

不得默认沪深300的旧样本代表全体主板，不得默认旧555种价格结构表达了本方向。
可自主提出一个日频首版，解释为何适合该方向；这不是复现5分钟经验卖法，报告中必须区分。
未运行、未支持和数据缺失均明确展示，不能以准备完成冒充策略已验证。

## 2. 实施原则：先找已有解法，先交付完整的一次研究

每个工作包先做限范围的复用判断：仓库已有 → 官方/维护中的现成组件 → 最小项目接线。
判断结果合并写入一份 `reuse-and-gaps.md`，记录来源、适用版本、许可、兼容差异与采用/不采用理由；不另造长期选型项目。
选型资料可联网查官方文档，但不得因此上传本地数据、获取凭据或启动付费服务。

| 需求 | 优先复用 | 不应重建 |
|---|---|---|
| Codex发现工作流 | 官方用户范围Skill、MCP server instructions | 新聊天客户端、全局提示词平台 |
| 工具传输 | 官方MCP Python SDK，锁定经确认兼容版本 | 自写通用JSON-RPC/MCP协议；不把旧单公告server改成平台 |
| 提案与准入 | `application/proposals.py`、`proposal_mcp.py`、`research_mcp.py`、现有DSL/compiler | 任意模型代码直接进入执行器 |
| 研究与回测 | Qlib Workflow、Record Templates、DatasetH/LGBModel、Exchange/Simulator及既有adapter | 自有订单/交易所/组合会计引擎 |
| 历史与任务 | 现有Ledger、artifact store、job/campaign/adaptive事件、锁与恢复 | 第二套权威数据库、通用调度平台 |
| 公告 | Evidence Store、`evidence_mcp.py`、本地导入、引用与proposal/admission | 把引用定位等同语义正确，把回购试点等同通用新闻审核 |
| 反馈研究方法 | 参考微软RD-Agent的hypothesis/experiment/feedback拆分及可复用实现 | 直接迁入其任意代码执行和整套多代理循环 |
| 比较和展示 | 已有retained reader、研究报告、Qlib原生指标 | 为了图表重跑旧科学；以MLflow界面代替 immutable artifact |

采用现成框架不等于安装全部依赖。新依赖放独立工具环境或明确optional extra，不能升级/覆盖已接受的科学环境和默认SDK pin。
先根据保留的耗时、容量和接口判断，再安装或运行；不为了“测性能”重做历史重任务。

## 3. 首版产品结构

### 3.1 一个用户入口，两类受控能力

新增面向用户的 `quantos-research` Skill（名称为拟议名，实际交付时核对冲突），配合本地STDIO MCP服务。
用户范围安装使其在不同工作目录可发现；服务器配置绑定固定解释器、入口和数据根，不能依赖调用会话的cwd。
运行中的研究包绑定精确源码/输入身份，服务升级不把新源码身份冒充旧任务来源。
Skill说明“先查已有证据、自动设计、只问实质问题、反馈可继续或停止”；工具层负责约束实际执行。

当前Codex会话承担研究设计和解释，默认不再嵌套一次研究SDK调用。
开发侧模型分工与产品运行时模型是两件事：任意可用Codex模型可使用工具，科学执行没有LLM。
外层会话提案使用明确的 `host-session proposal` 后继身份，保存用户brief、提案正文、公开依据和工具提交记录；
模型/思考强度等无法观察字段记未知，不伪造SDK capture、AgentRun或历史受认证模型身份，不保存私有思维链。
旧typed入口若不能接纳该身份，新增最小版本化适配，保留旧拒绝和历史回放。

### 3.2 拟议工具表面（设计意图，不是现存命令）

| 能力组 | 用户意图 | 必需行为 |
|---|---|---|
| 能力/数据描述 | 现在能研究什么 | 返回范围、数据起止与更新时间、费用未知项、已实现/未实现，避免自报全能 |
| 历史/证据查找 | 以前做过吗、依据在哪里 | 复用Ledger检索；返回逻辑ID与来源，不要求模型遍历大文件 |
| 创建/准备研究 | 按这个方向设计研究 | 保存brief及版本化proposal；自动解析已有绑定、编译、报价；准备不执行 |
| 执行/状态/取消 | 开始研究、进度如何、停止 | 调用现有执行层；持久任务ID；重复提交去重；授权预算由服务端检查 |
| 结果/比较 | 得到了什么、与简单办法比如何 | 同时报告工程状态、科学状态、预测/账户指标和限制；null不填零 |
| 公告读取/引用/审阅 | 材料说了什么、是否支持结论 | 读取冻结材料，定位原文，结构化提案及人工确认；未admit不作确定性事件特征 |
| 模拟准备/推进/查询 | 固定策略在新数据上怎样 | 复用Qlib逐期执行及持久账本；初版按显式调用推进，不默认常驻交易服务 |

以已有类型和服务为准，能合并的操作合并；不按表另造七套状态机。
MCP进程不能因为会话关闭就静默丢失作业：复用现有supervisor/持久job；若无法脱离会话安全运行，明确取消/待恢复并保留真实退出。
跨会话查找依靠持久任务索引；“继续上次研究”有多个候选时先列出，不靠可变latest路径启动canonical任务。
多会话可读，默认单重任务worker；共享authority/授权消耗/提交/取消保持顺序和幂等。
不用工具参数或模型自报的 `approved=true` 代替真实用户授权绑定。

### 3.3 每次研究产出

复用现有artifact/schema，最少覆盖：

- 方向、硬边界、偏好、模型自选项与理由、支持/缺失能力；
- 具体可执行策略及经典方法来源、代码/配置/数据/政策身份；
- 数据曝光情况、设计/选择/最终评价日期，信息可用时间；
- 对照、预算、随机种子、候选与失败分母、停止规则；
- 实际执行/成交/费用/风险/结果来源、失败与未评估项；
- 简短解释和下一步proposal，与确定性报告分开。

按需显示详细追溯，日常回答先说结论、依据和下一步，不让用户阅读内部契约字段。

## 4. 策略生成、比较与反馈的产品规则

### 4.1 自动设计有边界

默认一次先设计 **1个主策略**，查阅并使用成熟方法。常规参数由模型选定并说明理由，不逐参数问用户。
策略必须落入已接受能力；缺能力时先给出准确差异，不能将自然语言或任意Python作为准入逃逸。
必要的新数据/策略能力在开发线新增版本与适配，不让运行时Agent现场修改科学代码、门限或grammar。
价格规则不强制训练LGBModel；需要预测模型时复用其既有路径，避免为了“完整流程”增加无关训练。

**完整策略不是一个因子AST。** 当前 `contracts/research.py` 的指数成员、TopK、等权、周调仓/下一开盘，
以及 `contracts/backtest.py` 的日频执行与固定策略实现，都是需要逐项核对的旧限制。
U2/U3必须新增最小明确的产品执行profile，表达数据范围、特征/信号、选股、仓位、买卖/调仓、费用与风险约束，
优先接入Qlib原生策略和允许配置；历史profile继续按原规则运行。每个支持项都要有实际实现，不以任意策略JSON或代码生成器冒充通用执行。
第一版可限定为日频、有限原生策略/算子及配置组合，但必须足以表达一项与用户方向有关的完整策略；
需要5分钟支持才成立的方案明确受阻，不为保留旧周度链而把短线需求无声替换。

“股东人数减少”“知名机构持仓”“成倍放量”等是候选解释，不是已验证事实因果。
公告模型输出保持proposal；首版可把风险解释附在报告，不能未经准入就用它决定历史交易。
若公告不进入策略计算，必须明说“量价策略＋辅助公告分析”，不能宣称已验证联合策略。

### 4.2 小而明确的对照

首个研究包建议1主策略、1固定简单经典策略、5个事先固定种子的随机选股运行，并展示适用市场基准。
这是可修改的**准备建议**，不是科学预算授权，也不是足够证明统计显著性的样本量。
按实际报价收敛；如预算无法容纳，先重新准备并说明解释范围，不能观察结果后删除失败种子或挑对手。

比较先写清目的：默认随机只改变选股、保持可交易范围、买入日/仓位/退出/费用等条件尽量一致，检验选股增量；
不能把这种对照解释为整套研究系统相同总预算下的普遍优势。
经典对照采用公开明确规则，结果前固定配置；统一本金、市场、日期、费用、交易约束，暴露差异另列。
所有真实候选/变体/重复/失败均计入搜索历史；模板和AI同池管理，来源保留，不因AI来源优先。
不做“一组试更多方案取最大值”与另一组单次结果的无成本优势宣称。

### 4.3 时间与结论边界

先固定训练/选择/评价划分。已反复曝光的2015–2025等历史不能重新命名为独立盲测；旧sealed不自动开放。
有未曝光数据才谈独立评价，否则报告“回顾性探索”，并把新数据前瞻模拟作为后续来源。
所有因子/公告以当时已可获得信息为准；旧供应商历史非vintage限制继续显示。
输出收益、费用、回撤、交易次数/换手、实际风险暴露、子期表现、成交受限与缺失数据；预测指标不冒充账户收益。

旧Validation及P14c合同原样保留。短线任务若不适用旧周度政策，提出明确的后继政策及理由，**在结果前**固定；
不得因为旧换手阈值不通过就临时放宽。未完成正式Validation时仍可给有来源的探索报告，但明确 `NOT_EVALUATED`，不授策略资格。

### 4.4 反馈与停止

首次包默认没有自动修订科学额度；模型可以基于结果提出下一版，并说明哪条证据支持改动。
未来包可预授权最多1次有依据的修订，预算和比较方案必须事前包含；不默认无限搜索。
已授权包内自动推进到终态，不逐步问“继续吗”。STOP是合法动作，但应说明未答问题与重启条件。
框架新候选执行能力用独立的受控工程用例验证，不强迫模型为补能力证明生成无价值真实实验。

## 5. 模拟盘范围

首版交付**模拟能力的准备/推进/查询接线及离线演练**；真实前瞻模拟是独立运行阶段。
使用冻结策略版本和后续实际到达的新快照；信号形成后才执行，不能把回放历史数据称为前瞻模拟。
Qlib支持的执行频率/现金/持仓连续性须先核对，复用原生Exchange/Simulator/Position持久产物；
若原生接口无法满足当前方案，交付具体缺口，不能自写账户和成交撮合来凑完成。
T+1、涨跌停、停牌、手续费、滑点和可成交性按股票类型与交易日期适用规则处理；不假设信号bar的收盘价必然可成交。
没有盘中数据就不实现5分钟反弹退出，不用日线高低价猜测盘中先后顺序。
不中途换规则；新规则创建新策略版本与模拟任务。保留模拟成交假设，不能宣称与真实券商成交等价。
默认显式调用推进，每次先采集并冻结、再离线执行；不自动安装后台定时任务或承诺关机仍工作。
第一次真实包写明观察期限、推进频率、最大采集/执行次数、预算与结束条件；本计划不启动无限模拟。
回测不理想时可以建议停止；模拟模块仍可工程交付，不以策略盈利作为产品验收条件。

| U8 条件性前瞻模拟 | 固定策略、数据与有限观察包获授权后推进 | 实际新数据记录与观察结果；到期停止；不把尚未经过的未来时间写成已验证 |

依赖：U0→U1接口；U1后U2/U3可按稳定接口分工；U4可以在U1后独立推进；U5依赖U3/U4集成；U6汇总实际实现。
U7/U8的外部条件不妨碍U0–U6可独立完成部分。U1的只读可用入口可先交用户，不等所有功能完成才发布。
默认首版不是只读查看器：U2/U3是核心；若真实方向数据缺失，交付准确阻塞并完成其他能力，不能宣称全目标完成。
U0尽早判断主板历史范围、同花顺板块/历史成员、成交量与公司信息的真实可用性；SH/SZ代码约束不等于主板筛选。
所需数据不足时立即给一次集中的实质选择，不等开发结束才询问，同时继续不依赖该选择的接入与工程工作。
同花顺在本轮是板块来源偏好和用户人工交易工具，不包含连接其交易/模拟账户或操作软件下单的授权。
U5先完成本机安装与跨会话使用；模拟接线只采用已核实可用的原生接口。若缺口超出薄适配，保留条件性模拟未实现，
交付独立差异与建议，不为了它阻塞U2/U3核心，也不把前瞻信号日志称为已有模拟账户。

## 7. 模型与思考强度分工

以下是基于任务复杂度的工程分配建议，不是模型实验结论。2026-10-22官方文档建议Sol处理复杂编码、Luna处理明确重复工作；
思考强度由本计划按风险指定。实际可用性以会话工具为准，不购买额度或切换账户来满足分工。

| 角色 | 模型 / 强度 | 工作与边界 |
|---|---|---|
| M 主代理 | **gpt-6.1-sol / high** | 需求、架构、授权/资源、接口冻结、集成、最终验收和真实运行包；主会话始终保持全局目标 |
| A 研究与执行核心 | **gpt-6.1-sol / high** | U2/U3核心、host提案来源、策略与对照时间语义、Qlib接线、恢复；一名owner掌握紧耦合链 |
| B 工具与公告接入 | **gpt-6.1-sol / medium** | U1传输、U4、用户安装和薄工具；涉及安全/权限/幂等争议时提升到high或交M |
| C 明确整理任务 | **gpt-6-luna / high** | 官方资料清单、既定格式文档、固定报告展示、引用/链接整理；不得裁定PIT、改变科学门或独立设计研究协议 |
| R 定向复核 | **gpt-6.1-sol / high** | 在稳定接口/集成节点复核有实质风险的差异，返回可定位问题；不全仓重复审计 |
| E 疑难升级 | **gpt-6-astra / high** | 仅Sol已定位却未解决的跨层身份/恢复/统计设计矛盾；给有限输入和明确退出问题，不常驻 |

最多M＋2个子代理同时活动；C/R/E替换空闲worker槽，不额外常驻，不递归委派。科学与安装重任务仍单worker。
U0可分配A读执行链、B读接入/数据，各自产出短缺口；M定接口后再并行写不同文件。
每次spawn显式给模型、强度、任务边界、必要文件、预期产物和禁止动作。支持`fork_turns`的宿主若跨模型要求`none`，使用`none`并传精简任务包。
工具不支持指定模型时，记录实际继承值；可由现有模型串行完成，不假称已切换，也不让用户维护多个窗口。
不默认xhigh/max/ultra或Fast/Ultrafast。开发会话/子代理消耗与研究SDK调用、科学units分别报告，未知费用不估造。

共享schema/注册表/lockfile/全局配置/Git index由M独占；worker仅写明确分配文件。
只有冲突风险需要时才建隔离worktree，不复制科学环境和大数据。工具CLI与Skill均消费U1真实接口，不能自行猜接口并反复返工。
主代理可以依赖已核对交接，不重做所有worker工作；Agent复核意见仍是proposal，不代替程序结果。

## 8. 自动化、授权与资源

### 8.1 启动后连续完成的默认开发范围（以启动指令为准）

- U0–U6实现、官方资料检索、有限版本依赖准备、定向工程验证、文档、本地提交和本机接入。
- 研究设计可以由当前Codex会话生成；不因此授权嵌套研究SDK、额外账户、市场采集或真实科学批次。
- 复用已有适用授权；普通代码选择、参数提案、可逆接线不用再问用户。
- 用户级安装仅增改本产品条目，保留可恢复的原配置，不覆盖其他MCP/skills/模型设置；受宿主sandbox限制时走正式审批。
  配置备份留原权限和本机私有位置，不把可能含秘密的全局配置复制进仓库/报告。
- 用户只需启动一次主会话。主代理自动分工、接续未完成工作、汇总必要问题；不会承诺关掉Codex后持续运行开发。

### 8.2 一次可审阅的真实运行请求

U6必须先完成实际包、来源核对、依赖和容量报价，再集中询问用户是否运行；不是每个阶段询问。
报价写明新增采集/模型/科学次数、复用次数、wall与宿主总增长上限、已知货币费用及未知项、外发内容/接收方、超限停止与不自动重试。
没有可核验预算或必要数据，就交付缺口与选择，不伪造READY或可直接执行的命令。
未来批准必须绑定实际包；用户回复后在该范围内自动跑到终态，不逐轮确认。旧任务剩余额度不得转移。
数据获取也复用“采集→新不可变快照→离线研究”；供应商有接口不等于账号有权限、已购服务或历史时点可靠。
拒绝/失败保留；UNKNOWN不重发。无权限、未知实际退出或缺源时只对账/交接，不无限恢复。

### 8.3 资源与Git

先从历史记录取得实际量级，按已有StorageGuard/宿主卷映射/并发预留/安全余量准备开发与运行包络。
不先声明任意GiB一定足够；需要重任务而无法核定资源时停该动作，继续独立轻量工作。
首选已核验环境；新MCP工具依赖隔离，固定版本公开包的下载安装仍需遵守网络与资源权限，不读取或输出秘密。
本地实现可独立任务分支提交；默认不推送、PR合并、部署远端或运行券商交易。
仅提交本次源代码、配置模板、文档和必要测试；不上传artifacts、市场/公告原文、全局配置或凭据。
旧研究和失败父任务不改写；新提交身份不替代历史证明身份。

## 9. 比例适当的工程完成标准

只有用户发送含验证授权的启动指令后才新增/运行测试。复用受影响用例，新增检查集中在真实边界：

1. 从仓库外工作目录发现能力并查询历史；独立客户端上下文查到同一持久任务，不靠前一个会话记忆。
2. 方向能生成受支持的完整策略proposal；普通参数不推给用户；不支持的能力给明确差异。
3. 受控输入走通提案→准入→Qlib执行/已有结果采用→比较→反馈；真实市场研究与fixture结果分开。
4. prepare无执行副作用；重复提交不重复执行；并发写串行；取消/未知退出/已完成结果恢复不伪造成功。
5. 时间信息不足、未来数据、越界路径和未授权执行被拒绝；外层Codex身份不伪造SDK来源。
6. 随机种子与完整分母固定；缺失结果不填零；工程成功不覆盖REJECT/NOT_EVALUATED。
7. 公告结论能定位来源；未审阅提案不直接成为策略特征；来源范围缺失不输出“没有利空”。
8. 模拟演练复用Qlib账户产物、策略版本固定，历史回放与真实前瞻明确区分。

不默认完整CI、历史矩阵、全量数据复核或新模型性能比赛；发现真实变更影响再扩大必要范围。
真实客户端只读工具调用属于连接验收，不等于真实新策略科学执行。
若独立会话需用户操作，交付一个可直接粘贴的验证提问，未实际操作前不声称跨会话已验收。

完成报告分别列：实现完成、工程检查完成、已安装可调用、首个真实研究就绪/受阻/已运行、前瞻模拟未启动/观察中/结束。
这些状态不能合并成笼统“全部完成”。盈利不是工程完成条件，只有只读入口也不是核心产品交付完成。
