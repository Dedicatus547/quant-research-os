# 公告理解对照：实施计划

日期：2026-10-20。状态：计划，尚未执行。配套[启动指令](announcement-understanding-pilot-start-2026-10-20.txt)只有用户实际发送后才构成其所列实施授权。

## 目标与取舍

检验一个有限问题：对一种公告、一个固定抽取任务，AI 相比关键词/规则基线是否提高信息准确性，或减少实际人工修订工作。
本轮不检验投资收益，不生成价格因子，不训练预测模型、不回测，不重启已暂停的价格路线。
保留“AI 提案，确定性程序校验和评分，人工裁定原文歧义”的权威边界。
暂不建设多代理委员会、通用搜索平台或新的执行引擎。

采用依据：

- [研究暂停决策](../../artifacts/research-next-decision-20261020/decision.md)仅暂停既有价格路线。
- [P13 v2](../p13-v2-freeze.md)只证明单公告、带引用提示的有限范围，作为已曝光开发示例，不进入新的独立评价集。
- [Evidence 采集](../guides/acquisition.md)及[Agent 架构](../architecture/agent-and-campaign.md)规定来源、引用、permission 和 admission 边界。
- [实施纪律](../guides/implementation-discipline.md)要求复用、持久记录与比例适当的验证。

本计划中的样本数、任务输出和预算安排是建议设计，不声称已有实现、材料或资格。

## 自动执行范围

用户发送启动指令后，主会话连续完成 A0–A4；遇到某一依赖缺失，继续其他不依赖它的工作，最终集中报告。
不逐步询问“是否继续”。默认单代理，无并行重作业。

允许本地盘点、文档、有限脚本/配置接线和必要的定向实现验证；默认不提交、推送、部署、安装依赖、联网采集或调用研究模型。
正常开发会话自身消耗与研究模型调用分开说明，不能声称开发零成本。
真实公告使用/外发权限、人工参考答案和实际研究调用预算不得由代理自行批准。
单凭本计划不能写入授权记录或启动 A5。

## A0：采用已有状态，建立一个持久交接

1. 读取 AGENTS.md、实施纪律、当前状态、本计划及上述来源。记录实际 HEAD、已有变更和相关输入位置。
2. 主工作区已有文档改动和 `scripts/holding_retention_study.py` 保持；不得 reset、stash、clean 或覆盖。
3. 在 `artifacts/announcement-understanding-pilot-20261020/run-01/` 建立 `handoff.md`。若已有同任务目录，先核对任务身份和实际进程，再续接；不覆盖失败。
4. 复用现有代码和环境，不重跑 P13、历史科学、全仓测试或安装库存核验。按实际变动解释必要的补做范围。

完成：有明确任务范围、已有变更记录和可续接位置。不要另建任务管理平台。

## A1：材料盘点与自动选题

先读已有 Evidence manifest、目录索引与 P13 benchmark 声明，再按需读取少量对应原文。
发现具体路径后记录精确来源，不猜造路径或遍历所有市场数据。

输出 `inventory.json`，每条至少包含：

- 原始来源、内容 hash、原文与派生文本位置、parser 身份；
- 公告类别、公司、日期和事件关联；无法判定保留未知；
- 本地处理权限、研究使用权限及外发权限分别记录其依据；
- 是否已进入旧模型请求、旧 benchmark、历史人工检查；已曝光与未知分别保留；
- 重复、修订、同一事件后续公告及可读性问题。

本地盘点不自动授予研究使用或外发权限。历史 SZSE `UNKNOWN` 不当作已批准。
P13 单公告许可不扩大到其他材料；synthetic fixture 不计真实样本。

类别选择仅根据材料与标注可行性，不查看任何新 AI 或基线评分：

1. 权限与来源能够确认；
2. 原文可读，关键字段可定位；
3. 具有多个独立事件，而非同一公告的重复版本；
4. 含可比较的状态差异或相近但不属于目标事件的材料；
5. 能复用当前 schema 或轻量适配。

最多列出三个类别的可行性，推荐一个；优先已有材料，不预设回购等类别一定可用。
建议试点总量 24–40 份、开发约三分之一、评价约三分之二，实际按独立事件组划分。
这是探索性规模，不作统计效力保证；不足时缩小结论为可行性观察，不能靠复制或切碎同一事件凑数。
若只有旧 P13 示例，则交付材料不足结论及准确采集需求，不启动真实比较。

完成：`inventory.json` 和 `task-design.md` 写明唯一任务或明确缺口；此后不因成绩差换类别。

## A2：任务、对照与参考答案

在 `task-design.md` 固定：

- 输入是完整冻结文本或统一、确定性的截断版本；两方法可见信息一致。不得只给 AI 提示答案位置。
- 最小输出：目标事件是否存在、发行主体、事件状态，以及至多两个该类公告实际适用的关键字段；各结论必须有原文引用。
- 可输出未知/歧义；不得把“未披露”自动填为零，不推断原文没有的日期或金额。
- 明确日期含义、金额单位、范围数值、否定句、多事件和修订处理。超出本轮 schema 的情况记录为不支持。
- 参考答案依据是原文，不是股价、既有策略 verdict 或另一个模型的投票。

按公司/关联事件/修订链分组，避免同一事件跨开发和评价集泄漏。
样本清单和 split 在模型结果产生前冻结；抽样规则、未知曝光和历史重复都保留。
本试点不是市场 sealed confirmation，不使用或修改旧 sealed 区间。

代理可生成 `annotation-review.csv` 的建议标签和引用，但全部标记为未批准。
参考答案须由记录在案的人工审阅形成，或采用适用范围可证明的已有独立人工标注。
“引用存在”只能自动证明位置正确，不能证明语义标签正确。
评价集参考答案不得进入被测模型请求、基线开发输入或少样本示例。
若同一开发会话已读取评价答案或原文用于设计，应记录曝光并降低结论，不能称盲测。

人工审阅集中成一份表：材料、建议标签、引用、歧义与需确认项。
不能因用户未回答就视为确认。人工未完成时，继续接口分析和 fixture 实现，但真实比较保持未就绪。

## A3：最小离线实现与定向验证

先检查实际 P13、Evidence reader、proposal/citation 和 SDK adapter 接口，记录可复用组件与缺口。
优先复用；仅在 schema 可局部表达、不会改变冻结 authority 合同时新增研究专用接线。
若需要广泛改 contracts 或执行器，交付差异建议后停止该实现分支，不升级成平台改造。

最低交付行为：

1. 固定规则基线：关键词/正则/确定性解析，只按开发集调规则，保留版本。
2. 模型输入构建：绑定文本、prompt、schema、模型配置和每条样本 ID；不附评价答案。
3. 响应导入与校验：结构、引用范围和数值单位检查；格式失败和越界保留，不能免费再调用模型修复。
4. 离线评分与报告：能读取基线结果、真实捕获的模型结果、批准标签和固定 split。
5. 持久运行状态：复用现有 reservation/receipt/退出记录；已知完整结果复用，调用状态 UNKNOWN 不重发。

未来若有运行入口，应区分只读描述/核验、基线执行、模型执行与报告；提供实际 `--help` 核对过的命令。
不能在真实接口尚不存在时写“可直接运行”命令。fixture 响应不冒充模型产物。
不得调用市场训练、回测、验证 gate 或 Registry 为文本试点凑资格。

只验证新增重要行为：字段缺失与拒答、单位/范围、引用越界、跨样本串联、失败计入分母、
评价标签不进入请求，以及重复启动/UNKNOWN 不重发。
优先复用受影响既有用例，范围按实际改动确定；文档-only 不运行测试。
不得跑完整 CI、P13 资格矩阵或真实 provider 探路。结果只说明本次实现行为。

轻量准备持久新增写入预算为 256 MiB；共享原材料，不复制环境、市场文件或旧证据。
写入前估计体量，超过预算保存交接后报告；不删除独有证据、不自行扩额。
若出现重任务需求，先按已有宿主卷/并发预留/安全空间规则核算，不以 WSL free 替代。

## A4：冻结评估方式，交付可审阅运行材料

主评价建议为“整份公告任务成功率”：该样本全部必需字段与批准参考答案相符，且必需引用支持结论。
同时报告事件识别 precision/recall、字段准确率、引用支持率、拒答/格式失败率及各类样本分母。
非目标事件的正确拒绝应计分；不能靠大量空字段使总准确率虚高。
数值精度、单位换算与引用等价判定在看结果前明确；涉及语义歧义须人工裁定并留记录。

固定同一评价样本配对比较，缺失、格式失败和超时保留在原机会分母内。
只有具备随机化/平衡顺序及实际人工计时的审阅设计，才能宣称节省人工；
否则只报告质量与调用成本，人工时间记 unavailable。
报告样本数、差值、区间估计（仅在适用时）和事件聚类限制，不以单个最佳案例宣称优越。

在见到评价结果前，为这一个任务提出明确的实用改善门槛：
例如需要多解决多少份公告、容忍多少关键字段错误，以及值不值得对应费用。
没有用户业务价值依据时，报告描述性试点，不自动发明“通过即推广”的阈值。
小样本的结果只决定是否值得设计更大评估，不授予通用抽取或投资预测资格。

有足够材料和批准标签时，冻结新包，包括样本/split、答案版本、基线、prompt/schema、
源码与环境依赖、评价规则、外发范围、运行与停止政策。
尚缺标签或权限时只能交付 DRAFT，不生成貌似已获批准的正式包。

交付 `run-proposal.md`：

- 实际模型/runtime 支持范围，优先既有明确 profile，不自动升级或换提供方；
- 每样本至多一次研究调用、自动模型重试 0、UNKNOWN 不重发；总调用上限等于冻结评价样本数；
- 固定输入/输出 token 上限、任务 wall 上限、存储上限、失败停止规则；
- 已知价格/账户额度与未知项分开；不能把 token 或 policy units 当货币报价；
- 若未来预算不足，不暗中减少样本或挑选已完成成功项；保留不完整比较；
- 外发的具体文本类别和接收服务，不能只写笼统“允许联网”；
- 数据权限、人工标签、实现状态、运行依赖的 readiness；
- 真实命令及实际包 hash，或清晰的尚缺项。

未授权调用 provider 来估价或“测接口”。如执行前必须探路，它应包含在未来明确预算和分母内。
没有有效实际包就不生成可直接批准科学执行的文本。

A4 终态：

- `READY_FOR_APPROVAL`：准备就绪，等待对实际包的运行授权；
- `NEEDS_LABEL_REVIEW`：集中列出人工审阅表；
- `NEEDS_SOURCE_PERMISSION_OR_DATA`：列明具体权限/材料缺口；
- `NOT_WORTH_PROCEEDING`：没有合理试点价值；
- `IMPLEMENTATION_BLOCKED`：具体接口或环境缺口。

这些仅是本任务管理标签，不修改项目的正式科学或资格状态。
最终 handoff 必须说明 A0–A4 哪些完成、哪些未完成，不能把“已交接”称为“试点已完成”。

## A5：仅在实际包获批准后运行

本阶段不在默认启动授权内。将来用户批准实际包后，沿既有 guard/runtime 连续完成：

1. 核对源码/输入/预算/权限及实际资源；变化时只评估受影响部分。
2. 生成基线输出与模型输出，保留每次尝试、失败、使用量及实际退出。
3. 完成引用/字段校验与固定评分；语义争议集中提交人工复核，不自评为正确。
4. 自动生成配对报告、预算结算和清理记录，更新本任务交接。
5. 若无预声明的实用增益，结束本试点；不得更换 prompt 后在同一评价集反复尝试。
6. 若观察到增益，只建议下一独立研究。转事件信号、PIT/admission、市场回测均需后继任务。

结果是负面也正常收尾，不自动增加调用、不放宽评分、不重写旧报告。

会话与持久交接支持恢复，不保证关闭应用后后台运行。
