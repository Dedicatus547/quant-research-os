## 1. 目标、首版与完成的含义

目标：在明确的数据、工具和预算范围内，系统能够提出研究方案，执行检查，根据结果决定下一步，必要时生成新的方案，最终交付有证据的结论或有理由地停止。

建议首版暂称 `bounded-adaptive-research/v1`：**现有宿主 + 固定离线数据 + 现有安全表达式范围 + 有限研究轮次**。
程序负责核验、执行、记账和停止；模型只负责提出假设、表达式及下一步建议。一次启动后自动推进，不要求用户逐轮签发请求。
允许提出未在本任务中执行的新表达式；不增加字段、算子、任意 Python、在线数据工具或实盘能力。
“新”由表达式结构及任务历史判定，不声称发现了学术上的新方法。

两候选科学拒绝是有效研究结果。这个目标允许安全停止，也不要求每轮改善、策略盈利、跨宿主支持或所有故障都自动修好。
但停止必须说明已经知道什么、仍缺什么、为何不能继续；缺少原件时不得宣称研究成功。
反馈后的合理选择与长期研究收益分别验收，不能用“第二轮引用了反馈”证明质量提升。

**发布次序：**先交付可审查的离线开发版本；再以新授权完成最小本机真实组合，才能发布上述限定范围的运行版本。
离线通过时标为“实现及模拟验证完成，真实组合待验证”，不得提前标成完整自动研究。

## 3. 首版的一条完整路径

1. 操作员给出研究问题、冻结数据/政策、允许的表达式范围和新预算。准备器补齐固定身份，核对真实宿主空间、环境与授权。
2. 确定性程序读取已核验的相关证据，生成有限输入。若无预算、输入失效或任务已终止，直接交付停止报告，不调用模型。
3. 一次模型调用输出一个结构化决策：`PROPOSE` 或 `STOP`。`PROPOSE` 同时包含研究假设、安全表达式、来源引用和预期检查；后继方案还绑定父方案、反馈及修改理由。
4. 程序核对真实 capture、schema、来源和允许范围，去重并报价；先预留总预算，再冻结本次 singleton 子任务。模型不能自行发放额度或改验证门。
5. 复用既有离线 Qlib、PIT 和 Validation 执行，保留进程退出、结果与 receipt。执行失败、科学拒绝、通过分开记载。
6. 程序从核验后的原件生成反馈。还有决策机会才调用模型；模型可以提出新方案或停止，不能被预先规定“选另一个”。
7. 达到预算/期限、模型建议停止或遇到不能安全继续的状态时，生成确定性报告和交接材料。已完成结果即时持久化，不等最后一轮。

新的父任务仅承担有限轮次、事件引用和总预算；每个子任务仍使用冻结后的既有科学执行路径。
不得向已经冻结的 family 追加候选，不得通过新建子任务重置总预算或丢掉失败尝试。
依据相同数据反馈继续设计的结果均计入暴露历史，仍是回顾性探索；保留未暴露确认段，禁止用其结果引导修改后又声称独立确认。

模型调用最小化：预算/TTL/取消检查、静态准入、去重、执行、反馈提取、receipt 对账和最终报告均用程序完成。
不另外开“计划员—形式化员—总结员”三次调用；一个提案响应尽量同时提供假设和安全表达式。
JSON 无效、重复候选或范围越界保留原响应并按冻结策略停止；不暗中追加“修一下格式”的模型调用。
本轮不优化大型科学执行；已有耗时证据不足时不另造预测/回测捷径。

复用下层 singleton 科学路径。代码复用以实际前置条件为准，不把“函数已存在”写成“直接接上就可以”。

### 中断处理的最低要求

| 边界 | 允许动作 | 禁止动作 |
|---|---|---|
| intent 前，确认无启动 | 核对授权、期限及预算后按未启动处理 | 用一个未核验的状态文件推断没有副作用 |
| intent 后，调用是否发生不明，或响应未保存 | `UNKNOWN/RECOVERY_REQUIRED`，保留预留；只采用可核验的现存原件 | 根据本地 intent 推断远端发生/未发生，重新调用“补一份” |
| 响应已完整保存，业务未提交 | 核验后幂等补提交同一响应 | 再叫模型生成一次或覆盖原响应 |
| 科学 STARTED，没有完整结果/receipt | 先核对进程、独立退出及持久 checkpoint；仅在既有受支持恢复窗口内继续 | 仅凭锁消失或 timeout 重跑科学，伪造 exit/receipt |
| 科学结果完整，receipt 未发布 | 核验原始完成记录和依赖后只补发布/结算 | 重新执行科学来制造 receipt |
| 取消、过期、耗尽或无进展 | 阻止新的调用/执行，收集已有进程退出并只对账；按原语义保留已消费和未知占用 | 取消即退还未知费用、事后修改期限、把新预算写回旧任务 |

取消后已在途的工作按现有安全停止规则收尾，不能假设撤销远端调用或退款。
父任务与子任务之间的预留/发布同样需要幂等身份；一个子任务完成后再推进后继，不并发修改同一研究历史。

| 需证明的能力 | 最小输入/观察与预期 | 失败判据/未覆盖的内容 |
|---|---|---|
| 反馈可信传递 | 两种相反或不同的已核验反馈 fixture；检查实际输入投影和所引原件一致，错误哈希/错任务被拒绝 | 摘要自证、引用未进入输入均失败；离线模拟模型不证明真实模型会改变判断 |
| 分支和预算正确 | 可控模型替身分别返回 STOP、不同新 AST、重复/非法 AST；观察实际调用、执行次数与 ledger | 继续执行 STOP、越界执行、重复消费或漏计失败均失败；不以这个测试声称模型更聪明 |
| 中断安全 | 在上表具体持久化边界注入离线中断；已有完整原件可补提交，不明副作用停止 | 任何 UNKNOWN 重发或无 receipt 重算均失败；离线测试不是全部真实故障恢复证明 |
| 新候选真实接入 | 新 schema 的原始 SDK response → 结构 hash → 准入 → 冻结请求 → 科学退出/Validation/receipt | 只选冻结 ref、原件缺失或新 AST 未执行，均不能记作真实新候选能力已证 |
| 根据反馈做下一步决定 | 原始反馈实际进入后继请求；真实响应选择 STOP/修订/新方案，引用相关结果并说明动作依据；初始任务不规定后继动作 | 只有复述、动作早已指定，或错误解读拒绝原因，保留缺证。单链支持行为观察，不能独自证明因果改善或长期质量提升 |
| 有依据地结束 | 机器可读终态与简短人类报告对应完整事件、分母和预算；操作者可据固定入口复核 | 仅模型说“成功”、缺科学原件却给科学结论、把拒绝改成 PASS，均失败 |

哈希和 schema 证明身份/引用/规则，不能证明科学观点正确；进程记录证明某步确实运行和退出，不能代替结果核验；
CI/离线 replay 证明特定代码与场景，不证明目标宿主和远端协议；真实组合证明该固定版本/环境/输入的一条路径，不证明长期可靠。
P14d verifier 仅在实际申请相应资格且输入/接受范围适用时采用，不因本计划自动启动资格矩阵。

### 最小真实组合：开发完成后另给具体预算

新输出根、新任务身份、新授权，不复用耗尽的 A1 或 `29fef56` 额度。
建议首次上限：**2 次 SDK 决策机会、最多 2 个准入新候选、最多 2 次科学/Validation 执行机会；自动 SDK 重试 0，UNKNOWN 重发 0**。
第一次可提出新方案；执行后第二次可 STOP 或提出修订方案；第二个结果由程序报告，无第三次“总结调用”。
全部调用机会包括失败/非法回答，科学失败或重新启动同样占用执行机会；完整结果的 receipt 补发布不算重新执行。
执行和恢复的政策 units 依据最终冻结工作量报价，恢复不得越过总机会和总额度，不沿用旧 36 units 当作通用价格。
总 TTL、存储上限、真实宿主空间、并发预留、模型输入/输出边界和外发范围在运行包内填明。
token 观测、订阅余额和 policy units 分开记录，不声称次数上限是精确计费上限。

真实调用的必要性是新增的输出 schema/生成来源/反馈决策组合没有原接受覆盖；原 SDK 安装、Qlib 计算及未变科学门按依赖采用。
尽早使用已保存真实通知做离线协议回放；若仍需单次真实接口探路，计入上述总上限，不能额外免费重试，且探路本身不算正式接受。

| AR3 的字段投影、确定性报告及入口接线 | **GPT-6.1 Sol / Medium** | 涉及 authority、预算和恢复语义时回到 High |
| 证据路径清单、链接检查、runbook 整理 | **GPT-6 Luna / High**，`gpt-6-luna`，可选 | 只做明确输入到输出的辅助工作，不裁定科学接受或修复恢复状态；任务少时主会话直接做更省协调 |
| 新运行版的研究提案模型 | **GPT-6.1 Sol / Medium** 起步 | 沿用已接受模型/强度作为起点；新协议仍须单独组合验证。首次范围内冻结 profile，不逐轮换模型重试 |
| 运行操作会话 | **GPT-6.1 Sol / Medium** | 负责读包、核对、启动和交付；科学计算本身不调用 LLM |

不默认 Max/Ultra，不设永久“专家团”。开发模型与 runtime 的研究模型是两个配置；切换开发聊天模型不会更新已冻结的 SDK profile。
