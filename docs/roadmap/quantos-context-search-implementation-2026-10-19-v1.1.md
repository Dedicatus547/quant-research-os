## 2 论文依据及迁移边界

论文周期性复制已有工作区，以新的聊天上下文启动多个探索分支，再按外部评分选择后续方向。主实验的归一化均值为：单链 0.47、best-of-4 0.54、完整方法 0.78；11 任务消融中，单链、仅清上下文、仅分叉、完整方法依次为 0.45、0.55、0.57、0.71。两组实验不能跨行直接比较。[R1]

这些结果支持将状态重建与预算分配作为研究变量，但不能直接转译成 QuantOS 的收益或额度改善。论文 credits 按模型 token 计量，求解器与训练作业不消耗这部分 credits；其任务、交互形态与当前研究 SDK 不同。[R1]

本项目应区分两项假设：

1. **历史解释影响决策的假设**：新会话仍可能因显式 prompt 中的旧判断而沿用原来的方向。
2. **分支搜索改善预算利用的假设**：在可评价的多轮研究中，独立探索并选择后续可能优于持续投入一条轨迹。

本次诊断确认旧 rationale 实际进入后继输入并被引用，但未验证其有害因果作用；现有轨迹也不足以证明第二项已成为项目瓶颈。[D1] 改善投影不等于复现论文或证明逃离“思路盆地”。本次修订未重新审计论文实验，沿用 v1 的迁移边界。

### 3.3 尚未回答的问题与未来目标选择

首包主要问是否值得继续当前空间的搜索。后继包进一步询问：是否值得检查一个独立、非退化的平滑收益结构；若检查，其原生 G5 换手率能否达到冻结阈值 12。任务明确允许首次 STOP，模型实际行使了该权限，因此换手率仍未测量。[D1][R10][R11]

后续若决定继续研究，应先明确所要的结果：

| 研究目标 | 合理交付 | 不能据此宣称 |
|---|---|---|
| 让模型决定是否值得追加探索 | 有依据的 PROPOSE 或 STOP | STOP 已被证明比一次实验更划算 |
| 在限定成本内取得一个结构的阈值观测 | 依新任务约定完成选定结构的有效测量，或准确报告未完成原因 | 一次通过或拒绝代表整个 family |
| 判断历史意见呈现如何影响模型 | 预先固定比较变量、状态和评价目标的对照观察 | PROPOSE 更多就是研究质量更好 |

如果用户后来明确认为一次测量值得，应在新的任务中约定候选的选择与冻结方式、测量范围、停止条件和预算；复用现有执行能力。不要默默改写旧任务权限，也不需要为区分这些目标新增 runtime 模式。

研究实验可以在结果未知时有合理动机：需要明确它能区分什么、成本是否可承受，不要求预先证明结果必然有用。当前报告既没有证明那次检查不值得，也没有提供足以替用户决定追加成本的依据。本轮到此保留问题，不自动准备新包。

### 4.2 停止理由能支持多大范围

**首包。** 模型认为剩余预算和结构新颖性不足以单独构成新假说的理由，并明确没有声称所有允许假说失败。两份 Validation 原件为 `SUCCEEDED / REJECT`，G5 同时未满足 Sharpe 和换手阈值。B2 有 9 个冻结 request、6 个可分析来源、720 个共同日，`llm_minus_best_baseline=-0.0008272191343387846`。这些是有限来源下的观测。[D1]

首包自由摘要还包含先前 Discovery 支持暂停的研究判断。其引用的两份 `frozen.json` 绑定了生成批次，不能单独证明最终科学结果或暂停结论。pin 正确保证来源身份，不保证这句自由摘要已经逐字段验证。[D1]

**后继包。** 模型保留前次 STOP，明确该任务的换手率仍未评估。其实际依据包括历史换手率约 58.41、59.87（阈值 12）、B2 无正增量、组成部分比较缺失和没有本任务反馈。[D1] 上述历史候选结果不是独立平滑收益结构的匹配因果对照。

两包初始反馈为空是真实状态，不是继续探索必须满足而未满足的科学门。当前未发现足以把 STOP 判为违反任务约定的证据；也没有证明合法新检查的信息价值为零。

### 4.4 结构映射及其限定范围

两份真实 prompt 均只有 22 个已见结构 hash，没有可读表达式或完整未试目录，并且不允许工具调用。诊断复用共享 grammar、`structural_expression_hash`、`capability_rejection` 及已有 Qlib 翻译器，从绑定批次生成只读映射；没有把映射注入模型或据此选择候选。[D1]

| 数字 | 准确含义 |
|---|---|
| 39 | 三个已核对冻结批次的 mapping 记录条数 |
| 22 | 这些记录按完整 AST 去重后的结构数 |
| 11 | 上述完整 AST 中属于当前允许空间的结构数 |
| 555 | 当前 grammar 的完整结构总数 |
| 20 | `Mean(Return(close,h),s)`、s>1 的独立完整结构；均可静态准入，与所查批次完整 AST 的交集为 0 |

统计包含失败或拒绝的 proposal，不等于全项目搜索史、科学执行次数或成功覆盖。[D1] 应表述为“所查三批出现的完整 AST 中，有 11 个属于当前 555 结构空间”，不称为科学覆盖率，也不推导“剩余 544 个从未试过”。

独立完整结构没有出现，不表示相关数据未暴露：均值子树已在交互结构中出现。静态准入和局部批次中的新颖性，只证明存在合法动作，不能独自证明支付新实验成本合理。

诊断还指出，历史 delta 的 G7 top50 窗口 15/20/25 已有约 33.73/29.24/26.35 的观测。[D1] 重做这些观测不能冒充新问题，也不能替代所问平滑结构的原生 G5 测量。

| 错误值反例 | 把新增值伪造为 EXECUTION_FAILED 时，被原投影器以值不符拒绝 |
| 执行结果 | verify.py 退出 0，约 8.52 秒 |
| 核验范围 | 上下文依赖及既有投影器；不是新的完整包、环境或科学资格验证 |

以上是诊断报告的实际记录。[D1] 它采用已有小型原件及退出证明，没有重算科学、重读大型市场数据或重新校验 SDK 二进制；没有生产代码改动，也没有新增测试门或重跑全仓测试。

这足以验证新增字段对应原件、既有语义未被破坏，并且错误值会被拒绝。尚无新的模型输出证明补差改变 STOP、提高决策质量或降低成本。

### 5.3 后续采用方式

当未来确实需要建立引用该 selection 的新 recipe 时，在其正常准备流程中采用已验证字段，并检查最终冻结投影中的 `SOURCE_INCOMPLETE`。采用后再据实记录“新 recipe 已包含原因码”；在此之前，状态保持为“片段已验证，尚未采用”。

不为使片段立即生效而修改旧包，不为一个已能由现有格式表达的字段新增全局开关。若以后发现其他具体状态缺字段，再按实际风险在现有准备或投影入口最小补差；当前不启动通用字段完整性平台或额外资格流程。

## 6 条件性上下文对照

**当前状态：不准备、不启动 A/B。** “实际输入包含旧意见”这一条件已由诊断满足，但本轮只有合法 STOP，尚未确定哪种可观察差异足以支持改变默认策略。原因码完整性已有确定性反例验证，无需为它增加模型调用。[D1]

以下条件用于未来决策，不是要求先证明模型犯错才允许研究。若以后目标明确为测量输入敏感性，对照本身可以有信息价值；但敏感性不能自动解释成科学决策质量提升，也不因此触发本轮工作。

### 6.1 进入条件

未来若要准备模型对照，先明确目标是观察输入敏感性还是评估默认策略，并满足以下条件：

- 原件显示存在与假设相关的历史解释或呈现方式；
- 有一个尚未回答且能通过对照区分的问题；
- 两种输入能保持相同的研究对象、必要事实、动作范围和主要预算；
- 结果能够回答预先定义的研究问题，或影响是否采用该投影策略；若仅测量输入敏感性，应明确该结果不直接证明默认策略值得改变。

本次已确认后继包含旧 rationale；未来其他任务仍应依据各自实际输入判断，不能将本次观察泛化到全部请求。若研究关注的是“真实反馈后的解释如何影响下一步”，则必须有真实反馈状态；不能用两个不同任务的首轮请求冒充该状态。构造的离线夹具只能证明接线。

### 6.2 对照设计

初次只选择一个明确变化，不同时更换模型、思考强度、研究问题、数据范围或多个提示策略。

| 条件 | 说明 |
|---|---|
| A 当前策略 | 采用经核对的现有上下文构造 |
| B 待验证策略 | 维持相同必要事实和限制，仅调整预先选定的历史意见呈现方式 |
| 会话形态 | 两组都沿用当前新 thread，不添加额外 flush |
| 评估对象 | 依预先目标评价输入敏感性，或判断质量与成本 |
| 推论范围 | 输入敏感性或有限任务效果，不等于复现长期 Fork-and-Flush |

B 可以将历史观测与旧行动建议清楚分开，并明确后者可根据当前证据重新判断。若选择“省略非必要旧解释”作为变量，必须先证明它不是研究对象的必要定义，保留完整原件和所有相关负面事实，并在新对照设计中明确声明。

不能静默删掉暂停依据来诱导生成；也不能反复换措辞直到出现 PROPOSE。A/B 两组应预先固定，查看结果后的改版属于新的开发尝试，继续留账。

### 6.3 观察什么

若目标是改进默认策略，判断同等任务和资源条件下是否提高决策质量或降低成本；预先按任务写出哪些已知情形支持停止、哪些支持进一步检查，避免事后凭“看起来更积极”评分。

若目标仅是测量输入敏感性，则记录行动、理由及证据引用的变化与成本，仅报告对应条件下观察到的差异，不将其直接解释为质量改善。

可记录：

- 对原始证据、缺失和适用范围的理解是否正确；
- 建议动作是否可执行，是否能区分当前未决问题；
- 需要停止时是否有充分理由；
- 若处于真实反馈后状态，是否正确使用该反馈；
- 调用、输入输出 token、耗时、科学执行及人工核查成本。

PROPOSE 比例、新结构数和重复率仅作诊断。不能用另一个 LLM 的偏好评分单独宣布改善，也不能把一两次差异包装成统计显著或普遍能力提升。

### 6.4 如何形成可运行包

离线阶段先完成输入构造、来源映射、语义差异和评价规则。准备包必须填明实际任务身份、模型和环境、调用次数、数据外发范围、总成本边界、终止条件及输出位置。

运行包还须说明如何在现有身份和预算规则内，从同一已固定的预决策状态形成 A/B 两个独立请求，并预先划分每组预算与全局上限。两组原件分别绑定，全部实际费用和曝光共同留账；不得将 A 新产生的反馈、已见结构或余额变化自动作为 B 的初始输入，也不能重用旧请求身份或假定预算恢复。现有入口不能满足时，先交付这个接入缺口，不改写旧包或直调 SDK。

不在本文件中预设增加现有 2 次 SDK 或 36 policy units 的上限。对照中的新模型调用即使不启动 Qlib，也属于新的实际调用，必须计入相应范围；不能伪装成免费回放或隐藏在“总结”中。

使用已授权且确实覆盖该任务的范围即可，不重复请求同一授权。没有覆盖时，先完成可核对的运行包，再在实际执行前一次性取得所需批准。不得通过直调 adapter、新建 task 名称或更换目录绕过原有预算与执行边界。

**默认策略采用标准**：只有观察到与预先目标一致的质量或成本改善，才考虑采用新的默认投影。若结果接近、只有生成率变化，或成本更高而质量无明确收益，保留当前方案并结束该项改造。

## 7 长期分支搜索的后续条件

**当前状态：不实施。** 诊断仍未观察到有价值多轮轨迹、可利用的方向差异和每支足够反馈预算。[D1]

当前两次 SDK 机会若平均分给两个分支，每支只剩一次调用，无法让每支完成“提案—实际检查—根据反馈再决策”。这主要是首轮多次采样，不足以检验论文的持续研究与再次分叉机制。

未来只有出现以下实际需求，才讨论分支调度：

- 已观察到可运行且有价值的多轮研究；
- 同条件轨迹会探索不同方向，且差异有利用价值；
- 单链继续的边际信息价值降低；
- 每支有足够预算获得有意义的反馈；
- 仍有合法可探索空间和可信比较目标。

到时优先采用小规模、固定且可解释的策略。先比较连续研究与有限分支，并保留规则选择或无重复随机覆盖基线。不要因为论文使用多个分支，就默认开发树状调度器、动态停滞检测、常驻 worker 池、自动 K 调优或通用记忆平台。

将整个搜索过程作为评估对象。新的 thread 不会使数据重新变成未见样本；确定性回测和 PIT 正确性也不自动消除自适应选择偏差。[R12][R13]

需要保持：

- 分支选择使用的数据明确属于开发和探索；
- 最终评价的方法、指标和数据角色在看结果前确定；
- 未胜出分支可以停止执行，但全部实际尝试、费用和曝光留账；
- 共享祖先和市场样本的分支不作为独立金融证据；
- singleton 子任务不自动授予父搜索整体多重检验保证。

这些要求优先落实在现有 Ledger、预算和记录中，不为本建议新增一套统计平台。数据不足或评价不可信时，分叉无法修复该问题。

这部分针对使用 Codex 开发 QuantOS 的工作流，不属于研究 runtime 的能力资格，也不消耗或继承研究包的科学预算。

只有存在具体停滞问题时才采用这一做法，避免每个普通任务都复制两遍。开发会话成本单独记录，不能用“研究 SDK 调用为零”表示开发工作没有额度消耗。
