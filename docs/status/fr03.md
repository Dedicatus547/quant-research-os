# FR-03 状态与维护入口

资格状态基准：2026-09-29。结论为 **`NO_GO / THIN_MAINTENANCE`**；
P14d-C 为 **`BLOCKED_UNIMPLEMENTED`**。下列版本是已冻结/已观察的证据身份，
不表示上游最新发行版本。

## 当前证据

| 对象 | 已观察结果 | 可声明范围 |
|---|---|---|
| 历史 CLI P10 | 固定 CLI 配置的 9/9 spike | 该历史 capability evidence |
| canonical SDK/runtime `0.154.0` | Code Mode-aware P10 v3 为 6/9；`LIVE_EXEC_NOT_OBSERVED`；匹配 command lifecycle 为 0/4 | live SDK qualification `NO_GO` |
| 官方 candidate `0.156.1` | executable identity 已核验；account/read preflight 失败 | candidate P10 `NOT_EVALUATED` |
| 既有 A/B/C routing 观察 | 在修正 runtime provenance 后离线重分类为 `UPSTREAM_ACCOUNT_ROUTING_FAILURE` | 内部 subtype 仍为 `UNKNOWN` |
| P13 SDK 后续 | 未进入资格执行 | `NOT_EVALUATED` |
| P14d-C | 尚未实现 | `BLOCKED_UNIMPLEMENTED` |

历史 P13 v2 批准链与当前 SDK qualification 分别核对；
离线实现、shadow-chain 和历史 CLI 通过均不解除 live SDK 阻塞。

## 冻结维护政策

保持 canonical `0.154.0`、现有 P10 v3 rubric 和 9/9 硬门。
停止重复 prompt 尝试、新 D0.x 分支、CLI fallback 和双栈实现。

只有新的官方 runtime candidate，或实质影响 account/workspace routing、
相关 SDK runtime 边界的上游修复，才进入下一轮 qualification：

1. 核验官方 package、executable 与 provenance。
2. 运行一次最小 account/read preflight；失败即保留证据并停止。
3. preflight PASS 后，仅运行一次不变的 Code Mode-aware P10 v3：
   `gpt-5.6-sol`、`max_attempts=1`、rubric 9/9。
4. P10 9/9 后才允许进入 P13；P14d-C 仍需独立资格。

这些步骤是既有政策说明，本次文档整理没有启动 runtime 或 provider 调用。
